## 设计模式图元属性绑定变量 tag（DesignerV2 CoreQGraphics）

- 需求：设计模式下把图元原属性绑定到变量 tag；用户拍板三点：绑定表放图元内、
  tag 设计器手填字符串、先做单向读（数据→画面）。
- 方案：不造新系统，复用已有 `runtime/stage.py` 的 `TagBus`+`StageBinding`；
  缺口只是"设计态绑定信息没有通道进运行态"，补一座桥即可。
- 实现（5 个文件）：
  * 新增 `CoreQGraphics/g_binding.py`：`BINDABLE_PROPERTIES` 白名单（只放开
    context/checked/visible/stroke/fill_color/fill/opacity/strokeWidth/
    cornerRadius/font_size/widgetText/widgetValue，几何属性禁绑）+ apply
    枚举（text/bool/number/color/raw）+ `coerce`/`normalize_binding`。
  * `g_element.py`：`BaseItem` 加 `bindings()/binding_tag()/set_binding()`，
    存 `_page['bindings']`，走 `set_page_field` → 自动获得 JSON 序列化 +
    `PageHistory` 整页快照撤销；清空最后一条时删键，保持 round-trip 零改动。
  * `runtime/elements.py`：`RuntimeElement.apply_binding(field,value,apply)`
    只写实时显示字段（context/checked/_style/setVisible），**不写 _page、
    不置脏、不进 undo**——这是"运行态不污染设计数据"的关键落点。
  * `runtime/stage.py`：新增 `_control_apply`（widget 控件写值）；`load()` 在
    `widgets.rebuild()` 后调 `_load_page_bindings()` 扫描各图元 bindings 注册
    到 TagBus，`_page_bindings` 单独记账（reload 只清这批，不碰业务手动 bind）。
    apply 用 lambda 闭包捕获 field/apply，走 bind_element/bind_control（目标
    每次现查，换页不断线）。
  * `ui/property_panel.py`：新增"变量绑定"页（`_page_bindings`），每行 tag 输入框
    + apply 下拉；编辑走 `_commit`，tag 变更触发重建面板刷新 apply 可用性。
- 数据格式：`"bindings": {"context": {"tag":"dev.status","apply":"text"}}`。
  tag 是自由字符串，外部按同名 key 推给 `stage.tags.update()` 即可对上。
- 验证：项目 venv（`.venv/Scripts/python.exe`，PySide6 6.10.2）跑端到端脚本，
  18+7 项断言全过：设计态落盘/清空零改动、运行态刷新 context/颜色/可见性、
  _page 三处不被污染、reload 不重复注册、属性面板含 bindings 页、widget 控件
  绑定刷新且不污染。测试脚本在 `D:/tmp/bindtest/`（临时，未入项目）。
- 注意：DesignerV2 实为 PySide6(Python) 非 C++；`SceneMode` 已布尔化为
  `scene.is_run_mode`。`RuntimeElement.context` 原 setter 走 set_page_field
  （会污染），运行态绑定统一改走 `apply_binding`，不要直接用原 setter。

## 从 AppsManagers/DesignerV2 同步「填充样式 + 文本对齐」两项功能

- 背景：用户实际运行的是本副本 `AppsManagersV2/DesignerV2`（不是工作区那份），
  之前两次需求都只改在 `AppsManagers/DesignerV2`，本副本从未有过这两个功能，
  误以为被删。本次把两项功能移植过来。
- 两份差异判断（忽略 CRLF/LF）：`g_style.py`/`g_scene.py` 本副本 == 原始基线，
  直接整体覆盖为工作区新版；`g_elements.py`（本副本多一处文本描边
  `stroke.setAlpha(255)`）、`ui/property_panel.py`（多「变量绑定」页）、
  `runtime/elements.py`（多 `apply_binding` + g_binding import）有独立演进，
  一律**增量插入**，不覆盖，全部保留。
- 移植内容：`g_style.py`（BRUSH_STYLE_* / brush_for 带 style / Style.fill_style
  + text_align 字段与兜底）；`g_scene.py`（新建文本写 text_align=left）；
  `g_elements.py`（fillRect 用 s.brush() + drawText 走 text_align_flags + import）；
  `property_panel.py`（_brush_style_icon、填充样式下拉、文本对齐下拉、import、
  QtGui 的 QBrush/QIcon/QPainter/QPixmap）；`runtime/elements.py`
  （get/set_fill_style + get/set_text_align，import 并入本副本的 try/except 兜底）。
- 验证（本副本自身包 + offscreen）：5 文件 py_compile 通过；round-trip 零改动；
  填充下拉 15 项且每项有预览图标；对齐下拉左/中/右、存量显示 center、新建为
  left；运行态 4 个 get/set + apply_binding 共存；nav 含「变量绑定」页；
  page1 渲染 SHA256 与基线 `a451c571…` 逐字节相同。全 PASS。
- 结论：两份 DesignerV2 是**各自独立演进**的分叉，功能不再同步。以后给用户改
  功能前先确认目标副本；默认以本副本 `AppsManagersV2` 为准（用户实际运行的）。
