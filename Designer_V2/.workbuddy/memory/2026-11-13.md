## 设计视图四边刻度尺（两套坐标系）

- 需求：底边 / 右边新增刻度尺标识**场景坐标**，值保留 1 位小数；用户随后纠正
  **顶部 / 左侧标识的是视口坐标系**，不要四边混成一套。
- 最终口径：
  * 顶部 / 左侧 = **视口坐标**（视口像素位置 0 / 100 / 200 …，
    `_VIEW_RULER_STEP = nice_ruler_step(1.0) = 100 px`），固定，不随平移缩放变化；
  * 底部 / 右侧 = **场景坐标**（`mapToScene` 实时反算，随平移缩放变化）；
  * 两套数值都由 `ruler_label()` 统一输出 1 位小数。
- `g_view.py`：`_draw_rulers()` 四条带都画在视口像素层（resetTransform），
  `h_ticks/v_ticks(..., viewport=...)` 内部按口径选 step / 值域 / 像素映射；
  四个角块、四条红色光标线；`_ruler_strip_rects()` 四条带含 blit pad 扩展，
  pad 清零要求「同方向两条带都重绘过」。
- `ui/design_window.py`：tooltip 说明两套口径，开关 Ctrl+Shift+L 默认开。
- 验证：offscreen 挂 Arial 渲染，顶部 100.0~800.0 / 左侧 100.0~500.0，
  底部 -600.0~800.0 / 右侧 -400.0~600.0；两次缩放对比证明顶/左像素完全一致
  （diff=0）、底/右变化（diff≈13%）；1 位小数、无裁切重叠。
- 注意：offscreen 平台 QFontDatabase 字体表为空，截图验证需

  真实桌面无此问题。

## 旧页面 JSON -> Qt 原生坐标转换工具

- 需求：把旧 AGV 投影口径的 page JSON 转成 DesignerV2 能直接使用的版本。
- 口径：旧 `SceneProjection()` 默认 grid=50 / units=(200,200) / agv=True /
  origin=(0,0) => kx=ky=0.25；`point(x,y)=(-y*kx,-x*ky)`、`size(w,h)=(h*ky,w*kx)`、
  `angle=-a`、`rect(r)=(point(right,bottom), h*ky, w*kx)`。参数来源：
  `myGraphicsScene.grid_size=50`、场景构造里 `setSceneUnitsPerGrid(200,200)`、
  `is_use_for_agv_map=True`。`sceneRect` 保存的是旧场景坐标下的可见范围，
  新设计器 fitInView 用的是投影后的单位，因此也要一起 rect() 变换。
- 工具 `tools/convert_page_to_native.py`（纯 Python、无 Qt 依赖、可逆）：
  * 正向把投影烘焙进 center_pos / origin_pos / head_pos / end_pos / vertices /
    path_segments / width,height / radius_w,radius_h / rotate / length /
    style.cornerRadius / sceneRect；strokeWidth、font_size、widgetFontSize 等
    像素单位两边共用，保持不变；id/父子/zValue/name/context/图片路径原样保留。
  * `--reverse` 用 inverse_* 还原；`--mode identity` 只重序列化不改数值；
    支持目录/通配符批量、`--output-dir`、`--in-place`(自动 .json.bak)、
    `--dry-run`、`--force`、`--round`、`--mark`、`--keep-scene-rect`，
    以及自定义 grid/units/agv/origin。
  * 坑：`length` 必须按 k 缩放，不能用变换后端点重算（端点被 round(3)，
    原 length 来自更高精度端点，重算会破坏可逆性）；`rotate` 不能把 1e-15
    级浮点噪声归零，否则新旧 rotation 会有微小差异。
- 验证：旧 Designer.CoreQGraphics 加载原页面 vs 新 DesignerV2.CoreQGraphics
  加载转换页面，rack(1618) / page1(23) 逐 id 的 sceneBoundingRect、boundingRect、
  pos、transformOriginPoint、rotation、zValue **max diff = 0**；离屏
  `scene.render` 的 PNG **逐字节相同**；新包 `page_data()` round-trip 零改动；
  正反转换可还原原文件。
- 已生成副本 `rack_config_scene2.native.json`、`CoreQGraphics/page1.native.json`，
  原文件未动。项目里另有约 18 份旧页面在 `Designer/Core/data.json/datas/design/pages/`
  与 `res/myDesigner/scene/`，需要时批量转。
- 顺手修：`CoreQGraphics/__main__.py` 的 `open_designer` 原本只定义在脚本导入
  分支里，`python -m DesignerV2.CoreQGraphics` 会 NameError；已移到分支外、
  删掉调试 print，三处文档里的 `python -m DesignerV2.CoreQGraphics.ui` 示例
  改为正确入口。

## 开放线条闭合升级：交点 + 平面面提取 + 折线

- 需求放宽：**不必首尾相接，只要能围出封闭区域**；要计算交点；`polyline`
  折线也加入可参与类型。
- `g_outline.py` 由欧拉回路整体重写为平面排列（半边 DCEL）：
  * 所有段统一成参数化三次控制点（直线用退化控制点 p1=p0、p2=p3）；
  * 交点：线-线解析、线-曲线把控制点代入直线法向求三次 Bernstein 根
    （40 段采样 + 二分）、曲线-曲线 de Casteljau 双向细分 + AABB 剪枝；
    另把每个端点投影到别的段上识别 T 型接触；
  * 按交点参数切段（曲线保持精确 cubicTo，反向半边交换 c1/c2），
    交点/端点按 1.0 场景单位聚类成节点；
  * 半边 `next = prev(twin)` 面遍历，保留**正**有向面积的有界内面，
    每面一个 closedSubpath；悬空边来回走出的零面积环丢弃。
- 两个实测坑（都已修）：
  * 曲线在前 / 直线在后时 `_line_curve(b,a)` 返回 `(直线参数, 曲线参数)`，
    必须交换成 `(a 参数, b 参数)`，否则切在错误位置，弓形面提不出来；
  * Qt 场景 y 轴向下，面遍历的**内面是正面积**、无界外面是负；最初按负号
    保留，结果生成的是绕悬空伸出段走一圈的外边界（矩形巧合看不出来，
    交叉三角形 / 井字立刻暴露）。零面积判定仍用共线性检测而非 shoelace
    （8 字形正负面积会抵消）。
- 现支持：交叉成三角形、井字中间一格、端点落在别的线中段、端点伸出交点、
  多块独立封闭区域、直线×贝塞尔 / 贝塞尔×贝塞尔交点、折线封口与折线交叉；
  多子路径在 `path_segments` / `vertices` / 存盘 / 运行态都保持。
- 文案同步：右键 tooltip、编辑菜单 tooltip、状态栏、关于、`__init__` 包文档、
  `g_scene.apply_closed_path` docstring 全部改为「围出封闭区域」，并说明
  未参与封闭的悬空伸出段随源线条一起被替换（Ctrl+Z 可恢复）。
- 验证：offscreen 约 90 项全通过；6×6 交叉网格提取 25 个格子、总面积
  10000、判定+生成 15 ms；2/25 子路径存盘 round-trip、运行态、UI 撤销全过。
- 边界：不处理单条三次曲线的自交叶形与切线相切（不穿越、不成面）。
