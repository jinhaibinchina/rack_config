# 2026-11-04

## 运行态点击无反应（selectionChanged 不发射）

**现象**：`safety_car_main.py` 里 `scene.selectionChanged` 连了 `plc_safety.handle_selectionChanged`
和 `update_property_area`，运行态点击画面没任何反应。

**两个根因**：

1. `myGraphicsScene.py:900` 用 `selectionChanged = Signal()` 覆盖了 QGraphicsScene 原生信号，
   唯一的 emit 点在 `set_current_select_item()`，而所有调用者都在 `SceneMode.Design` 分支里。
   Run 模式的 `mousePressEvent` / `mouseDoubleClickEvent` 整段跳过选中逻辑 →
   `current_selected` 不更新、信号不发，两个槽等于死代码。

2. 站点组在运行态 `get_selectable()` 恒为 False。`base_element.set_visibility()` 隐藏时把
   `__selectable_last` 写成本次隐藏前的值，`hide_all_station()` + `set_visibility(True)`
   往返几轮后 last 被洗成 False，再显示就永远不可选。
   `plc_safety.handle_scene_mode_change(Run)` 能把站点组设成可选，但它在构造期没人调用
   （`set_scene_mode(Run)` 的 emit 早于图元入库），补调用也压不住 `on_item_changed()`
   里的 `set_visibility(False)`。**结论：运行态不要用 selectable 判定能不能点。**

**修复**（最小面）：
- `myQuadTreeScene.mousePressEvent` 的 Run 分支末尾补：先取 `_event_pressed_group`，
  不是 group 就退回 `_find_visible_group_at(pos)`，再 `set_current_select_item(anchor)`。
  只改 `current_selected`，**不** `set_selected(True)` —— 否则 `base_element.paint`
  会画设计期红色 id。
- 新增 `QuadTreeScene._find_visible_group_at()`：m_sorted_items 逆序，可见 + 顶层
  group_element + sceneBoundingRect 包含点。刻意不看 `get_selectable()`。
- `safety_car_main.update_property_area`：`current_selected` 初值是场景自身，
  补 `or selected_item is self.scene` 兜底。

**回归**：`tools/verify_run_selection.py`（14 项，offscreen + `enable_plc=False`），
覆盖设计态不受影响、重复点击不重复 emit、运行态无 set_selected、切站后点站点组能出面板。

## 设计态：组合组的显示/隐藏

**需求**：设计模式属性页里能设置选中组的显隐。

**改法**：
- `PropertyItem._state_card()` 抽出 `_visibility_widget()` / `_state_hint()` 两个钩子，
  默认仍是只读 label（单图元不给入口，藏起来画布上就点不中）。
- `GroupPropertyItem` 覆盖成 `make_check("显示", ...)`，toggled → `set_visibility`。
  `handle_visibility_change` 里补 `scene.set_current_select_item(self.item)`，把面板钉在该组上
  （同对象不 emit，面板不重建）。
- `group_element.set_visibility` 加成员可见性快照：隐藏时记 `_visibility_snapshot`，
  显示时按快照还原。**否则组内原本单独隐藏的成员会被一起点亮**，运行态
  `hide_all_station()` + `set_visibility(True)` 反复几次会把整场景冲成一片 True。
- `NavigationContentWidget.create_appearance_page` 末尾挂 `_hidden_groups_card()`：
  列出本页所有隐藏的顶层组，每行一个「显示」按钮 → `_restore_group()`。
  **这是唯一恢复入口**：`set_visibility(False)` 会把 `__selectable` 置 False，
  设计态 `check_hover` 直接 return False，隐藏的组在画布上根本点不中。

**回归**：`tools/verify_group_visibility.py`（16 项，纯构造无场景数据，用 `_FakeScene` 提供
`scene_manager.m_items` / `get_bg_color` / `width/height`）。

**测试坐标系坑**：`sceneToView()`（用 `scene_origin` + grid/units）和 `_event_scene_pos()`
（用 `offset` + `scale` + `view_x0`）是两套换算，scale≠1 时不互逆。
要用 `_event_scene_pos` 的逆运算求控件坐标：
`view = sceneToView(scene_pt) * scale + offset`。
QTest.mouseClick 还会按控件外裁掉越界点，改手工构造 `QMouseEvent` 直接派发更稳。

## 运行态选中的最终语义（用户自己改定，已提交 1dd2533，别再改）
- `myQuadTreeScene.mousePressEvent` 的 Run 分支：`anchor = self._event_pressed_group`
  （即 `_find_event_group_at` 的结果），**不做 `_find_visible_group_at` 回退**。
  所以只有「绑定了事件 / 可切换 / 可交互」的组点上去才会更新 `current_selected`。
- 普通站点组（如「安全门」，无事件绑定）点击**不抢选中、不发 selectionChanged**，
  站点说明面板不会因它刷新。用户明确要求保留这个行为。
- `_find_visible_group_at()` 仍留在文件里但已无人调用（用户保留，别删）。
- `mousePressEvent` 里有一行 `print(f"运行态选中组: ...")` 在热路径上，用户留着调试用，别动。
- 消费侧兜底放在 `safety_car_main.update_property_area`：非 `group_element` 直接 return，
  否则复选框被点中时面板会被切成图元属性页。
- `tools/verify_run_selection.py` 改成按图元实际能力（`has_event_bindings/is_toggle_enabled/
  is_interactive`）决定断言方向：能驱动的咬定选中，不能驱动的咬定「不抢选中」，14/14。
