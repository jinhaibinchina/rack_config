## 运行态点击无反应（selectionChanged 不发射）

**现象**：`safety_car_main.py` 里 `scene.selectionChanged` 连了 `plc_safety.handle_selectionChanged`
和 `update_property_area`，运行态点击画面没任何反应。

**两个根因**：

1. `myGraphicsScene.py:900` 用 `selectionChanged = Signal()` 覆盖了 QGraphicsScene 原生信号，
   唯一的 emit 点在 `set_current_select_item()`，而所有调用者都在 `SceneMode.Design` 分支里。
   Run 模式的 `mousePressEvent` / `mouseDoubleClickEvent` 整段跳过选中逻辑 →
   `current_selected` 不更新、信号不发，两个槽等于死代码。

2. 站点组在运行态 `get_selectable()` 恒为 False。`base_element.set_visibility()` 隐藏时把
   `__selectable_last` 写成本次隐藏前的值，`hide_all_station()` + `set_visibility(True)`
   往返几轮后 last 被洗成 False，再显示就永远不可选。
   `plc_safety.handle_scene_mode_change(Run)` 能把站点组设成可选，但它在构造期没人调用
   （`set_scene_mode(Run)` 的 emit 早于图元入库），补调用也压不住 `on_item_changed()`
   里的 `set_visibility(False)`。**结论：运行态不要用 selectable 判定能不能点。**

**修复**（最小面）：
- `myQuadTreeScene.mousePressEvent` 的 Run 分支末尾补：先取 `_event_pressed_group`，
  不是 group 就退回 `_find_visible_group_at(pos)`，再 `set_current_select_item(anchor)`。
  只改 `current_selected`，**不** `set_selected(True)` —— 否则 `base_element.paint`
  会画设计期红色 id。
- 新增 `QuadTreeScene._find_visible_group_at()`：m_sorted_items 逆序，可见 + 顶层
  group_element + sceneBoundingRect 包含点。刻意不看 `get_selectable()`。
- `safety_car_main.update_property_area`：`current_selected` 初值是场景自身，
  补 `or selected_item is self.scene` 兜底。

**回归**：`tools/verify_run_selection.py`（14 项，offscreen + `enable_plc=False`），
覆盖设计态不受影响、重复点击不重复 emit、运行态无 set_selected、切站后点站点组能出面板。

## 设计态：组合组的显示/隐藏

**需求**：设计模式属性页里能设置选中组的显隐。

**改法**：
- `PropertyItem._state_card()` 抽出 `_visibility_widget()` / `_state_hint()` 两个钩子，
  默认仍是只读 label（单图元不给入口，藏起来画布上就点不中）。
- `GroupPropertyItem` 覆盖成 `make_check("显示", ...)`，toggled → `set_visibility`。
  `handle_visibility_change` 里补 `scene.set_current_select_item(self.item)`，把面板钉在该组上
  （同对象不 emit，面板不重建）。
- `group_element.set_visibility` 加成员可见性快照：隐藏时记 `_visibility_snapshot`，
  显示时按快照还原。**否则组内原本单独隐藏的成员会被一起点亮**，运行态
  `hide_all_station()` + `set_visibility(True)` 反复几次会把整场景冲成一片 True。
- `NavigationContentWidget.create_appearance_page` 末尾挂 `_hidden_groups_card()`：
  列出本页所有隐藏的顶层组，每行一个「显示」按钮 → `_restore_group()`。
  **这是唯一恢复入口**：`set_visibility(False)` 会把 `__selectable` 置 False，
  设计态 `check_hover` 直接 return False，隐藏的组在画布上根本点不中。

**回归**：`tools/verify_group_visibility.py`（16 项，纯构造无场景数据，用 `_FakeScene` 提供
`scene_manager.m_items` / `get_bg_color` / `width/height`）。

**测试坐标系坑**：`sceneToView()`（用 `scene_origin` + grid/units）和 `_event_scene_pos()`
（用 `offset` + `scale` + `view_x0`）是两套换算，scale≠1 时不互逆。
要用 `_event_scene_pos` 的逆运算求控件坐标：
`view = sceneToView(scene_pt) * scale + offset`。
QTest.mouseClick 还会按控件外裁掉越界点，改手工构造 `QMouseEvent` 直接派发更稳。

## widget_element 复制丢尺寸/旋转中心（已修）
- 现象：改了尺寸和旋转中心的控件图元，复制粘贴后被打回控件 `sizeHint` 尺寸，中心回到 (0,0)。
- 根因：`_auto_fit_size()` 在只读态**无条件**用 `sizeHint` 覆盖 `setSize` + 四角 +
  `_center_pos`；而粘贴链路 `set_widget_visible(True)` → `_ensure_layer` →
  `_rebuild_widget` → `_auto_fit_size` 必然触发。`clone()` 本身是对的（尺寸/四角/
  `m_origin`/`_center_pos` 都拷了），**丢掉发生在挂载那一刻**，不是克隆那一刻。
- 修法：`_auto_fit_size(force=False)` 加一条前置判断——`scene_size` 已有有效值就直接
  return（说明用户定过尺寸）。`_rebuild_widget` / `set_widget_text` / `set_widget_readonly`
  调的是默认不强制版；需要重新贴合传 `force=True`。
- 连带行为：文本变长、切换控件类型都不再自动改边框尺寸（用户定过的尺寸优先）。
- **注意**：widget 图元的"控件旋转中心"是 `_center_pos`（`sync_widget_geometry` 里
  `layer.apply(center, ...)`），而右键"设置图元的旋转中心"设的是 `m_origin`，两者不是
  一回事；`_center_pos` 也不持久化（`to_dict` 里 `center_pos` 被注释掉，`from_dict`
  硬编码 0,0）。要支持 widget 自定义旋转中心得同时改序列化。
- 回归：`tools/verify_widget_clone_geometry.py`（13 项，前 6 项用 StubScene/StubLayer
  跑到 `_auto_fit_size` 层，后 4 项用真实 `QuadTreeScene` + `SceneManager` 走完整
  `copy_selected` / `paste`，并断言承载层确实建出来了——否则"没走到"也会假通过）。
- 场地坑：真实场景验证时 `mgr.addItem(item, False)` 必须带第二个参数；给图元手动
  预置四角会让 `scene.findChildren(base_element)` 找不到它，`copy_selected` 直接返回空。

## PopPick 动画在放大后卡顿（性能定位与修复）

**现象**：画面放大后交换动画明显掉帧。离屏软件渲染 1280×820、520ms 动画，
33 帧是 `QVariantAnimation` 16ms 间隔的上限：

    scale   改动前        只加位图缓存   缓存+跳过占位框
    0.5     33帧/16.0ms   33帧          33帧
    1.0     28帧/19.3ms   32帧          33帧
    1.5     18帧/31.3ms   28帧          33帧
    2.0     13帧/44.6ms   26帧          32帧
    3.0      9帧/64.0ms   18帧          33帧
    4.0     14帧/43.2ms   24帧          33帧

**根因两个（都不是动画自己，而是重绘）**：

1. **每帧重渲染真实控件**。proxy 带旋转后 `QGraphicsProxyWidget::paint` 每帧
   把控件从头渲染；且父窗口一脏，该区域下**所有**承载视图都被重画 —— 6 张卡
   只有 2 张在动，另外 4 张一帧不落地重新渲染。实测单次动画控件 paint 次数
   从 30~540 次降到 1~6 次。
2. **占位框照画**。`rect_element.paint` 的旋转矩形 100% 被真实控件盖住，但
   每帧仍做一次 AA 填充+描边。放大后一张卡几千像素见方，6 张就是 20~30ms。
   `widget_element.paint` 原注释写着"已覆盖就不画"，但两个分支都在调
   `super().paint()`，属于注释与实现不符。

**修复（都是动画开始打开、结束/中断立刻关掉）**：
- `EmbeddedWidgetLayer.set_motion_cache(active)`：proxy 切
  `ItemCoordinateCache`，分辨率 `min(2.0, max(1.0, scale))`。结束必须回
  `NoCache` + `proxy.update()`，否则静止画面发虚（缓存是定分辨率烘焙的）。
- `widget_element.set_widget_fast_paint(active)`：跳过 `rect_element.paint`，
  但**仍调 `base_element.paint`** —— 那里有 `_reset_moving_flag()` 和位置
  变化检测，漏了会让图元被当成"拖拽中"而拒绝命中。
- `PageDeck._set_fast_render(active)` 统一开关两者，作用到**所有**卡片。
- 判"控件是否盖住图元"要用 `layer.is_shown()`（`view.isVisible()` 的真实
  状态），不能用 `is_visible()`（那是"要求显示"的意图，窗口没 show 时也真）。

**代价/取舍**：
- 点下去到首帧约 50ms（6 张卡的缓存一次性烘焙），与优化前同一量级，之后
  全程 16ms/帧。
- 缩放 ≥2 时每张卡缓存 2048×1600×4 ≈ 13MB，6 张共 78MB，动画结束即释放。
- 跳过占位框的视觉差异只在窗口最左侧一条 76px 窄带（一张几乎全在屏幕外的
  卡的边框），实测差异 6091/1049600 = 0.58%，肉眼无感。默认关闭以保持设计器
  原观感，只有 PopPick 动画期间打开。
- 动画+重置后画面与初始差异 14/263451 = 0.005%（仅抗锯齿边缘），无残影。

**试过但没收益的**（别再重复）：
- 按两卡并集/`QRegion` 做局部 `scene.update()`：2.0 缩放 25→24 帧，3.0 才
  18→22，噪声级别，不值。
- 去掉 `_on_progress` 里的 `scene.update()` 整窗重绘：无提升（子窗口移动时
  Qt 本来就会标脏父区域）。
- 隐藏 4 张静止卡能省 14ms，但动画路径会扫过它们，躲不掉。

**注意**：`Designer/Core/myGraphicsScene.py` 的 `draw_bg`/`draw_grid` 里
`painter = QPainter(self)` 把传进来的 painter 参数覆盖了，所以 `backing_store`
从来没被填过，双缓冲实际只有 `dynamic_buffer` 在起作用。是既有隐患，本次
没动（改它风险远超收益）。

**回归**：`tools/verify_pop_pick_swap.py` 扩到 40 项（新增"静止不启用/动画中
全开/结束后恢复/中断也恢复/动画期间控件几乎不重绘"）。其余三套
（embedded_widget、run_selection 14、group_visibility 16、unified_entry 18）
全绿。性能探针：`tools/profile_pop_pick_perf.py`。

## PopPick 动画"画面失真"（缓存方案的坑，已改自烘快照）

**现象**：上一轮为了提帧率切了 `ItemCoordinateCache`，用户放大后截图：文字撑到
卡片外面、白底和黑边框错位、边角被裁成方块台阶、整片卡片糊成白色。

**根因（两个）**：

1. `setCacheMode(ItemCoordinateCache, QSize(w*r, h*r))` 里的 QSize **不是**
   缓存分辨率。Qt 会按这个"逻辑尺寸"去渲染控件，proxy 的内容就被放大了 r 倍
   再贴回原来的包围盒 —— 等价于把整张卡（含文字）放大。实测同一帧数字笔画数
   28→12（放大 2.3 倍），且随缩放成比例恶化。不加 QSize 则退化成 1:1 烘焙，
   放大后一样糊。**这个 API 不能用来提清晰度。**
2. 上一轮"跳过占位框"连**边框**一起跳掉了。卡片轮廓全靠这条描边，没了之后
   页面融合成一片白，也是失真的重要来源。实际只有"填底"是纯像素填充开销。

**改法**（`Designer/Core/embedded_widget_layer.py` + `elements.py`）：

- 动画开始时自己烘一张快照：`widget.render()` 到 `QPixmap(w*ratio, h*ratio)`，
  `ratio = clamp(scale × 屏幕DPR, 1, 4)`（另有单边 4096 上限）。插进内层场景
  的 `QGraphicsPixmapItem`，proxy 只 `setVisible(False)`（几何仍由它决定）。
  逐帧只剩"按角度贴图"，控件 paint 次数固定 6 次（≈每卡一次）。
- 快照位姿用显式 `QTransform`：`translate(中心) → rotate(-angle) → translate(-中心)
  → scale(1/ratio)`，再 `setPos(proxy.pos())`。QTransform 后调的先生效。
- 占位框改成"只描边、不填底"：新增 `widget_element._paint_widget_outline`，
  仍调 `base_element.paint` 做记账。**边框必须留**。

**结果**（离屏 1280×820，520ms 动画，33 帧是上限）：

    scale   改动前         现在        控件重绘
    1.0     31帧/17.5ms   33帧        361 → 6
    2.0     11帧/61.5ms   33帧        101 → 6
    3.0     11帧/56.5ms   25帧         77 → 6
    4.0     14帧/39.2ms   26帧         77 → 6

**验证口径**：快速渲染开/关两帧做像素比对，通道差>32 的采样点占比。
新实现 1.45%（离屏）/0.73%（真实字体，仅边缘抗锯齿）；旧实现 9.36%。
回归里用 3% 阈值锁住，直接防"文字被放大/卡片糊成一片"。

**如果要再提帧率**：剩下的成本是 6 张卡的描边 + 快照贴图，已接近这套架构的
下限；再压就只能砍静止卡的描边（会丢轮廓，不建议）。

## PopPick 新增「最大窗口」按钮

工具栏顺序：重置布局 / 适应窗口 / 最大窗口 / PLC。

**「最前面的两页」的口径**（踩过一次）：不能取 `stack_cards()[:2]`。扇形里
Z 最高的两张是相邻的，后一张被前一张整片盖住——结果只有**一张**卡撑满画面，
右侧当前页反而被裁掉一半。正确取法是「右侧槽位上的当前页 + 左侧堆叠最上层
那一页」，这两张才是各自完整呈现内容的两页。

实现上把 `_fit_view` 的落点抽成 `_show_scene_rect(rect, margin_ratio)`，
两个按钮共用：都是喂场景矩形给 `set_view_scene_rect`，内部
`_view_state_for_scene_rect` 反算 scale（含 `clamp(0.01, 10.0)`），
之后必须 `refresh_embedded_widgets()`，否则又是"黑框缩了、白卡不动"。

实测 1280×820 视口：适应窗口 scale 2.032 / 6 张全见；最大窗口 scale 2.851 /
两页 570×730 各一张，填充 97%×95%，两页均完整可见。交换后再点会跟着新的
当前页走（状态栏会报出是哪两页）。

回归 `tools/verify_pop_pick_swap.py` 46 项（新增 4 项：工具栏有按钮、放大生效、
两页都在视口内、主方向填充 ≥90%）。

## 最大视图锁定左侧最上层

需求（不是 bug）：点了「最大窗口」之后，左侧最上面那一页**不允许再点交换**。
那个状态是用来专注看这两页的，占满左半屏的卡最容易被顺手点掉。

实现：`PopPickWindow._maximized` 标志。
- `_maximize_view()` 成功后置 True，状态栏提示「左侧最上层已锁定」
- `_fit_view()` / `_reset_layout()` / 滚轮缩放（`eventFilter` 里的 `QEvent.Wheel`）都置 False
- `_handle_click` 里 `_is_locked_card(card)` 拦截：取 `deck.stack_cards()[0]` 现算，
  **不能缓存引用**——交换后最上层会换人，缓存下来会锁到已经跑到右边的卡上

只锁"堆叠最上层"这一张，其它卡照旧（最大视图下它们基本都被裁在视野外）。

排查过程记一笔：先怀疑命中/事件被承载视图吞掉，实测 `card_at` 正常、
`w.childAt()` 返回 QuadTreeScene、真实平台连点三次都能交换——说明不是 bug，
是需求表述。以后遇到"某某不可点击"先确认是故障还是预期行为。

回归 51 项（新增 5 项：不触发交换、状态栏提示、锁定保持、适应窗口解锁、
解除后同一张卡可交换）。
