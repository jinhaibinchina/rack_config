## 修复：page_2 图元"全部不可见"（sceneRect 过期）

**现象**：切到 page_2 后画面几乎空白，图元"都不见了"。page_1 / page_3 正常。

**根因**：数据层问题，非绘制裁剪 bug。
- page_2 有 1009 个图元，其中 850 个"料架"主体（料架1、料架1_2、…、料架1_5、料架1_2_2 等 8 个顶层料架 + 各自仓位）被布置在 y≈-87000 ~ -103000 的极远位置；另有 159 个"料架1_6"系列在 y≈-4000~+1000。
- 页面 `sceneRect` 字段记录的是"上次保存时的可见范围"，仍停留在 y∈[-26658,+19661]（只覆盖近处 159 个图元），与主体料架完全错位。
- 打开页面时 `deserialize_scene` 忠实恢复该 sceneRect → 视图对准近处空区域，主体料架全在视口下方 7~9 万单位外，看起来"全部不可见"。
- 实测：渲染 page_2 仅 575 个深色像素（vs page_1 的 15937），近乎空白。

**修复**（防御性，不改数据）：
`Designer/Core/myQuadTreeScene.py` 的 `SceneSerializer` 新增两个静态方法，在 `deserialize_scene` 恢复视图前判断 sceneRect 是否"过期"：
- `_items_bounding_rect(scene)`：所有顶层图元（parentItem is None 且 m_parent is None）sceneBoundingRect 的并集。
- `_view_rect_is_stale(scene, rect)`：sceneRect 几何中心到图元主体中心的距离 > 自身对角线 0.5 倍即判过期。正常页该比例约 0.2，page_2 达 0.89。
- 过期时改用整体包围盒 `set_view_scene_rect(fallback)`，确保打开能看见内容。

**验证**：
- page_1（比例 0.20）/ page_3（0.23）→ stale=False，视图原样恢复，无误判。
- page_2（比例 0.89）→ stale=True，视图扩展到全部图元（sence_y [-106726,5364]）。
- `tools/verify_render.py` 5 态像素 diff=0，starved=0；`tools/bench_scene.py` 1610 图元正常、四叉树 x1.00、on_mouse_move 1.0ms。

**遗留/注意**：
- 850 个料架主体为什么被放到 y≈-100000 仍需用户确认（可能是正常扩展布局，也可能是某次成组/复制操作甩飞）。本次只做了"打开能看见"的兜底，没有动数据坐标。
- page_2 图元 y 跨度约 11 万单位，fit 后 scale≈0.05，图元会缩得很小——这是数据布局本身决定的，非本次修复引入。

## 新增：widget 嵌入式 QWidget 图元（场景内嵌真实 Qt 控件）

**需求**：能否在场景中嵌入 QWidget，并做一个这样的控件。

**结论**：场景是纯自绘 `grid_map_window(QWidget)`（非 QGraphicsView），**不能用 QGraphicsProxyWidget**。采用"真实 QWidget 子窗口 + 手动坐标映射同步"方案。

**实现**：
- `elements.py` 新增 `widget_element(rect_element)`：`type="widget"`；持有 `_host_widget`（真实 QWidget 子窗口）+ `_widget_factory`（控件工厂，默认 QLineEdit，可用 `set_widget_factory(lambda host: QPushButton(...))` 自定义）；`paint` 设计模式画占位框+"Widget"字样；`to_dict`/`from_dict` 存 `widgetText`/`widgetType`。
- 几何同步 `sync_widget_geometry()`：复用已验证的 `viewBoundingRect()`（场景→视图，正确处理 AGV x/y 交换）+ `rect_viewToWindow()`（视图→窗口像素），避免自行重算坐标约定。
- `setPos`/`move_by`/`setSize` 后自动同步 host 几何。
- `myQuadTreeScene.py`：`set_scene_mode` 里切 Run 时 `_sync_embedded_widgets(True)`（创建+显示真实控件）、切 Design 隐藏；新增 `_sync_embedded_widgets_geometry()` 在 `wheelEvent`/`mouseMoveEvent`（平移分支）后刷新几何；`deserialize_scene` 加 widget 分发；`createItem` 加"控件_"命名分支。
- `element_factory.py` 工具箱加"控件"项（160×40）；`myGraphicsScene.py`/`design_page.py` import 同步。

**关键修复（顺手）**：`SceneManager.createItem` 的 isinstance 判断顺序——`rect_element` 分支原在 `checkbox_element`/`widget_element` 之前，导致这两个 rect 子类被命名成"矩形_"。已把 checkbox/widget 判断提前到 rect 之前。

**验证**：命名（控件_1/复选框_1/矩形_3）、几何对齐（host 几何与 viewBoundingRect→rect_viewToWindow 完全一致）、move_by 后同步、序列化往返、模式切换显隐、自定义 QPushButton 工厂均通过；回归 verify_render diff=0、bench_scene 无破坏。

## 修复：widget_element 不响应旋转 → 禁用旋转

**问题**：真实 QWidget 无法旋转（Qt 原生限制），widget_element 的占位框会转但真实控件不转，出现"边框转了、控件没转"的错位。

**方案（用户选择）**：禁止旋转 widget 图元，始终保持水平。

**实现**（`elements.py` 的 `widget_element`）：
- 重写 `setRotation` 和 `rotate_to_ang` 为 no-op（阻断 Ctrl+滚轮、属性面板、代码等所有旋转入口）。
- `from_dict` 强制归零：旧数据若存了非零 rotate，反序列化时用 `m_transform.rotate_around(-angle)` 抵消并置 `m_angle/m_angle_init=0`。
- `paint` 去掉 `painter.rotate(-angle)`：占位框始终与真实 QWidget（水平轴对齐）一致。

**验证**：widget 的 setRotation/rotate_to_ang 后角度恒 0；rect 对照组正常旋转到 45°；from_dict(rotate=77) 归零；回归 verify_render diff=0、bench_scene 无破坏。

## 结论：widget 内嵌控件的字体不随缩放（机制定位）

真实 `QLineEdit` 是 `QWidget(scene)` 的子窗口，由控件树绘制；场景缩放只是 `paint` 里的 `painter.scale(scale_factor)`，只作用于场景自绘内容。`sync_widget_geometry` 只同步 `setGeometry` 的像素宽高，从不改字体，所以框会缩放、文字恒为默认 9pt。修法：捕获 `_base_font` 后按 `scale_factor` 重设字号的补丁已给出（未落地，等确认）。

## 验证：overlay QGraphicsView + QGraphicsProxyWidget 方案（可旋转 + 可输入）

**产物**：`tools/overlay_widget_probe.py`（独立验证台，`--shot` 抓图 / `--selftest` 自动回归）。

**架构**：不迁移主场景，只在控件矩形上盖一层透明 `QGraphicsView`（无框、NoFocus、`WA_TranslucentBackground`、FullViewportUpdate），内部 `QGraphicsScene` + `QGraphicsProxyWidget`。
- 缩放放 `view.setTransform(scale)`，旋转放 `proxy.setRotation`（`transformOriginPoint` = 控件中心），`NoCache` 保锐；
- view geometry = **旋转后包围盒 × scale**，以图元中心为中心；`sceneRect` 设为旋转后 bbox 使内容铺满视口。

**实测结论**（selftest 全通过）：
- 旋转 30° 后点控件中心 → `QLineEdit.hasFocus()=True`、`cursorPosition=12`，命中与光标定位全由 Qt 算，**无需手写逆变换派发**；
- 键盘输入、IME `QInputMethodEvent` 都能进控件（commit 生效）；系统候选窗仍需人工用中文输入法确认；
- 缩放时**文字跟着一起缩放且是矢量锐利**（2.0x 截图对比明显），顺带解决上面的字体问题；
- 包围盒空白角**不会吞点击**：QGraphicsView 未命中 item 时 `ignore` 事件，会自动冒泡给父场景（实测主场景收到左键）——原担心的"透明区吃事件"是伪问题；
- 偏差：geometry 取整会让旋转态下虚线框与控件有 ~1px 错位，可接受。

**待定**：是否把 `EmbeddedWidgetLayer` 接进 `widget_element`（替换 `_host_widget` 的裸 setGeometry 方案）。接的话要处理 z 序（`raise_()` 跟 zValue）、页面切换销毁、设计模式 hide。

## 落地：widget_element 改用 overlay QGraphicsView 承载（字体缩放 + 旋转都解决）

**新增**：`Designer/Core/embedded_widget_layer.py` 的 `EmbeddedWidgetLayer`（view + inner_scene + proxy 三件套，`apply(center, design_size, scale, angle)` 一个入口）。

**改动**：
- `elements.py` 的 `widget_element`：`_host_widget` → `_layer`；删除 `_ensure_widget`/`_relayout_widget`；新增 `_ensure_layer`/`has_widget_layer`/`raise_widget_view`/`Delete`（先回收层）；`sync_widget_geometry` 改为算「中心点 + 设计尺寸」交给 layer；`paint` 在 Run 模式直接不画占位框、并恢复 `painter.rotate(-angle)`；**解除旋转禁用**（删掉 setRotation/rotate_to_ang no-op 和 from_dict 里的强制归零）。
- `myQuadTreeScene.py`：`_sync_embedded_widgets` 走 `set_widget_visible`；新增 `_restack_embedded_widgets` 按 zValue 排 `raise_()`。

**踩到的三个坑**（都写进 MEMORY.md 了）：
1. `addWidget` 前先 `setParent(viewport)` → proxy 静默接管失败（`proxy.widget()` 为 None），控件变成普通子窗口 → 渲染完全不旋转；
2. 只 `widget.setFixedSize` 不同步 proxy → 包围盒要等下一轮事件循环，几何算成 1x1；
3. `proxy.resize` 被控件 minimumSizeHint 卡住（QPushButton 宽 80）→ 必须先 `setMinimumSize(1,1)`（给 0,0 无效）。

**验证**：`tools/verify_embedded_widget.py` 21 项全过（设计模式不建层 / 1.0-2.0-0.5x 几何 / 30° 包围盒 / zoom+rotation 组合 / 自定义工厂重建 / 删除回收）；`tools/verify_render.py` diff=0；截图确认占位框与真实控件同向同心、2x 下文字矢量放大。
**副作用处理**：冒烟脚本用 `DesignWindow` 会在退出时重写 page_*.json（多出测试图元 + set 顺序变动），已 `git checkout` 还原四个数据文件。

## 修复：控件"点得进去但打不了字"

**现象**：运行模式点进 QLineEdit 后键盘无反应，英文同样不行。

**根因**：承载 view 建的时候写了 `view.setFocusPolicy(Qt.NoFocus)`。点击时 `QGraphicsScene` 仍会把 proxy 设为 focusItem 并给控件一个"逻辑焦点"（`widget.hasFocus()==True`），但 `QGraphicsView` 自己不接受系统焦点，`app.focusWidget()` 留在主场景 `QuadTreeScene`，按键被主场景吃掉——`QGraphicsView::keyPressEvent` 是键盘进代理控件的唯一入口。

**修法**：`view` 与 `view.viewport()` 都设为 `Qt.StrongFocus`。

**验证**（真实 Windows 平台，非 offscreen）：
- 点击中心 → `app.focusWidget()` 变成承载 view，`view.hasFocus()` 与 `widget.hasFocus()` 均 True，`keyClicks` 写入成功；
- 两个控件来回点，焦点与文本互不串；点场景空白 → 焦点回 `QuadTreeScene`，按键不再进控件；
- 离线运行场景复刻（`scene.setFocusPolicy(Qt.NoFocus)` + Run）同样能输入。
- `tools/verify_embedded_widget.py` 新增「真实点击 + 真实按键」3 项断言，全量 25 项通过。

**设计边界**：设计模式不挂真控件（只画占位框），因此在设计模式下点控件输入无效是预期行为，不是 bug。



## 控件上左键拖动不能平移画布 → 承载层补"延迟派发"

**现象**：鼠标停在 widget 控件（承载 overlay 视图）上时，左键按住拖不动画布，但滚轮能缩放。

**原因**：场景的平移是 `myGraphicsScene.mousePressEvent` 设 `panning=True`、`mouseMoveEvent` 里 `offset += delta`。控件矩形上的鼠标事件被 `QGraphicsView` 整体接走，场景根本收不到 press。

**做法**（`embedded_widget_layer.py`）：
- `EmbeddedWidgetLayer` 改成 `QObject`（不挂 parent，由 `dispose()` 显式 `deleteLater`），在 `view.viewport()` 上装 eventFilter；
- press 先扣住不转发 → move 超过 `QApplication.startDragDistance()` 判为拖动画布（写 `scene.offset` / `last_pos`，`update_coordinate()`，再 `_sync_embedded_widgets_geometry()` 让所有承载视图跟着动）；不超阈值则在 release 时补发 press+release 给 viewport（点击、取焦照常）；
- 两次快速点击补一个 `MouseButtonDblClick`（否则 QLineEdit 双击选词、列表 doubleClicked 会丢）；
- 补发前先 `view.setFocus()` + `widget.setFocus()`：QGraphicsProxyWidget 处理 press 时会按 scene 焦点项重同步焦点，事后设会被覆盖（这一点在 verify 的"点击命中"断言上复现过）。

**验证**：`tools/verify_embedded_widget.py` 扩到 29 项（新增"拖动平移 40x20"、"视图跟随位移"、"微动不触发平移"、"微动算点击"），全过；`verify_render` diff=0。真机（windows 平台）复测：拖动 60x30 → offset 与 view 几何都位移 60,30；单击后控件获焦、`xyz` 输入成功。
**坑**：测试脚本手动设 `view_x0` 时必须同时按 `offset = -view_x0*scale_factor` 设 offset，否则 `update_coordinate()` 一调就跳（真机 scale≠1 时暴露，offscreen 用 scale=1 掩盖了）。
