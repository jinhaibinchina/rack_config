## 字体下拉剔除 GDI 位图字体（DirectWrite 告警）
- 现象：运行设计器时刷 `qt.qpa.fonts: DirectWrite: CreateFontFaceFromHDC()
  failed ... for QFontDef(Family="Terminal", pointsize=9, pixelsize=12 ...)`
  （还有 `Fixedsys`，pixelsize=16）。
- 根因：`QFontDatabase.families()` 里包含 Windows GDI 位图字体（`Terminal` /

## 修 DesignerWindow 构造崩溃：sceneModeChanged 接不上
- 现象：`DesignerWindow(page_path, projection)` → `GraphicsView.__init__` 里
  `self.scene.sceneModeChanged` 报 `'builtin_function_or_method' object has no
  attribute 'sceneModeChanged'`。
- 根因（两处笔误，都在工作区未提交的 WIP 里）：
  1. `self.scene` 少了调用括号，拿到的是 `QGraphicsView.scene` 这个 C++ 方法，
     不是场景对象；同一个 `setScene()` 里其他地方都写的是 `self.scene()`。
  2. `set_scene_mode` 发的是 `self.sceneRectChanged.emit(bool)` —— 那是 Qt 内置
     信号、载荷 `QRectF`，真正的自定义信号 `sceneModeChanged` 声明了却没人 emit
     （一旦走到那行会直接 TypeError）。
  3. 槽里 `self.show_grid(not run)`：`show_grid` 在 `__init__` 里是 **bool**
     属性（`self.show_grid = True`），不是方法，调用即 `TypeError: 'bool'

  - `g_scene.set_scene_mode` 改发 `self.sceneModeChanged.emit(self.is_run_mode)`。
  - `g_view` 把连接搬进 `setScene()`（与 selection/structure/itemChanged 同一处
    连/断），切页换场景会重新接一遍——只在 `__init__` 连一次的话新场景没人订阅。
    文件里那个 `getattr(scene, "sceneModeChanged", None)` 兼容老场景实现。
  - `on_scene_mode_changed(run)` 只 `viewport().update()`，**不改 `show_grid`**：
    它是「视图→显示网格」的用户偏好（`toggle_grid` 同时改 `show_grid` 与

## 刻度带「拖动画布留残影」的真正根因（上一版只刷 t 厚不够）
- 现象：拖动画布后，画布顶部往下堆出一片阶梯状灰条纹（重场景 1618 图元明显）。
- 实测（真实窗口 + 屏幕抓取 vs 全量 grab 逐像素比）：旧实现 6.29% 不一致，其中
  y<120 有 90 行差异；新实现 0.85%，`y<120` **0 行**，剩下的都是图元边框/文字
  在局部重绘下的 1px 差异（虚线相位 / blit 取整，与标尺无关）。
- 机制：`QGraphicsView` 平移动画走 blit（`viewport()->scroll`），**每次把刻度带
  的像素往画布里推 |dy| / |dx|**。只重画 [0,t] 那条时，推出去的一截（t..t+|dy|）
  留在画布上，下一帧再推一段、再留一截 → 累积成阶梯。
- 修法：`_ruler_scroll_pad=[px,py]` 累计推出距离（封顶视口尺寸），
  `_ruler_strip_rects()` 按 `t+pad` 出厚度标脏；`_draw_rulers(painter, exposed)`
  用 `mapFromScene(exposed).boundingRect()` 判断「整条带（含 pad）真被重绘了」才清零。
  **不能用 `painter.clipBoundingRect()`**：QGraphicsView 的 drawForeground 没有设
  clip，返回空矩形，条件永远不成立 → pad 无限增长。
- 探针 `tools/probe_pan_ruler_smear.py`（真实显示环境跑，离屏没有 blit）：
  输出 old/new 两组的 diff 比例 + 实况/全量/差异图到 `tools/_out/drag_*`。
- 门禁 8.31 补断言：带厚随 pad 加厚、pad 累计后整带重绘清零。
- 全量回归：主 / UI 429 / 布尔 / 增量 / 运行态 / draw_snap / 字体 / child_move 全 EXIT=0。

## 框选 text 图元卡顿：三条独立成因 + 修法
- 现象：设计器里框选（橡皮筋）明显卡顿，text 图元尤其；page_1（1618 图元 / 103 text）。
- 实测（Windows 平台，1600×900，QTest 拖 20~24 步取每步中位）：
  整屏 193ms/步、中等区域 63ms、小方块 37ms。
- 成因 1（改不了，只能降单帧成本）：Qt `RubberBandDrag` 把 band 画在视口画布上，
  每移动一格重画整个视口 —— 日志里 `drawBackground` 收到的暴露矩形恒等于整页
  （6645×3955）。所以每帧就是「一帧全画 1618 图元」。
- 成因 2：每改一次选中就 `property_panel.update_for_selected`（12ms，`_clear()` +
  重建控件）+ `LayerTreeDock.sync_selection`（21ms，整树 walk 攒 QItemSelection）
  + `_refresh()`。全屏拖一趟触发 17 次 ≈ 700ms 纯 UI 重建。
- 成因 3（text 专有）：`TextItem.paint` 先 `painter.boundingRect(r, AlignCenter, text)`
  量紧凑矩形再 `drawText` 进去 = 同一串字每帧排两次版。实测 text paint 168µs/个，
  rect 只有 19µs；103 个 text 每帧 17ms。
- 修法：
  * `GraphicsView._refresh_selection_dirty()`：`viewport().update()` → `updateScene(rects)`，
    只标脏「标记占的区域」（bbox ∪ 中心→支点线段，外扩 10px/scale）。超过
    `_MAX_SELECTION_MARKS`(200) 时前景层不画标记，只把上一批标记擦掉。图元自己的
    选中虚线框由 Qt 在选中状态变化时 update 图元区，不归这里。
  * `_sel_geom_dirty`：`geometryChanged`（新增 `_on_geometry_changed` 连接）后缓存
    脏区作废，下一次选中变化整屏刷一次，避免「拖过再取消选中」留残点。
  * `GraphicsView.selectionSettled` + `is_band_selecting()`（左键按空白处置位）：
    窗口 `_on_selection_changed` 框选中只置 `_selection_pending`；松手
    `_flush_selection()` 一次重建；`LayerTreeDock.set_defer_probe(view.is_band_selecting)`
    让图层树自己那条 `scene.selectionChanged` 订阅也跳过。
  * `TextItem.paint`：`drawText(r, Qt.AlignCenter | Qt.TextDontClip, text)` 一次排版。
    逐像素比对 6 种情形（短/溢出/多行/0.4~3.0 缩放/中文）全部 0 差异；300 text
    单帧 83→52ms。
- 结果：整屏 193→99ms、中等 63→20ms、小方块 37→19ms。剩下 ~19ms ≈ 一帧全画
  （热态），是 Qt 橡皮筋固有成本；再往下要自绘 band（只标脏两条窄条）或给图元开
  `DeviceCoordinateCache`（实测 90→51ms，但缩放要重建缓存）。
- 门禁：UI 门禁加 §8.36（7 条：标记区增量标脏、换选中同样不整屏刷、框选中不重建
  面板、图层树探针、松手一次同步、松手后树选中一致），444 → 451 全绿。主 197 /
  字体 42 / 增量 27 / 运行态 26 / 布尔 56 / draw_snap 30 / unified 62 全 EXIT=0，
  safety 47 / rack_paras 48 / rack_stores 58 全绿。
