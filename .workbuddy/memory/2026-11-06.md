## 业务 key 不用再加数字后缀（继承 11-05 的 OPC UA 工作）

**用户反馈**：导出的映射里 `alarmcode_2` / `timestamp_2` 这种 key 不好，
应用层找 tag 不该用带后缀的变量名。这些其实是
`Alarms2HMII[0..4].AlarmCode` 等数组元素，短名撞车后硬加序号把数组语义丢了。

**修法**（公共函数放 `tools/opcua_json.py`）：
- `semantic_key(node_id, path, name, depth)`：优先从 NodeId 的 `s=` 标识符
  （去掉 `|var|` 前缀）按 `.` 切段，取末尾 N 段；`_norm` 把 `[0]` 变成 `_0`
  保留数组下标、GBK 代理项先 `clean_text` 还原成中文、其余符号变下划线。
  不传 path 优先是故意的：扫描路径末段可能只有 `[0]`，会退化成 `0_alarmcode`。
- `build_unique_keys(items)`：**不冲突的点保持短名**（`aallowmovejogn`）；
  同名点自动多取一层父级，得到 `alarms2hmii_0_alarmcode` …
  `alarms2hmii_4_alarmcode`；只有整条路径都相同的真重复节点才退化成序号。
- 三处统一：`opcua_browse.build_subscription_map`、GUI
  `_collect_mapping`、`opcua_from_json.load_tags`。

**`tools/opcua_from_json.py`**：
- `load_tags(path, key_style="path")`，`JsonTagClient(..., key_style=...)`，
  CLI `--key-style {path,flat}`（flat = 旧行为，兼容既有映射文件）。
- 新增 `--dump-mapping FILE`：不连 PLC 就写出 `{endpoint,count,nodes,detail}`
  干净映射，供业务层固化。
- 打印变量表时用 `clean_text()` 包一层，否则中文 NodeId 里的代理字符会让
  stdout 抛 UnicodeEncodeError。

**现场产物**：`globalvars_tags.json`（从 `globalvars_structure.json` 生成，
391 个点，`opc.tcp://192.168.1.88:4840`）。
注意 `btn_moveto_p_workstation_2` / `btn_teach_p_workstation_2` 里的 `_2`
是**设备侧变量名本身**（`btn_moveTo_P_WorkStation_2`），不是人为后缀。

## App_LogPlot / log_plot_main.py：PyQt5 → PySide6 迁移

**范围**：根目录 `log_plot_main.py` + `App_LogPlot/app/**`（15 个 py）。

**机械替换**：`PyQt5`→`PySide6`、`pyqtSignal/pyqtSlot/pyqtProperty`→
`Signal/Slot/Property`、`exec_()`→`exec()`。

**只能手改的四处**（Qt6 结构性差异）：
- `QAction` / `QShortcut` 在 Qt6 属 `QtGui`，`PySide6.QtWidgets` 里**没有**
  （不像 PyQt6 还留着转发），凡是 `from ...QtWidgets import QAction` 都要搬。
- PySide6 没有 `uic` 模块：`plot_moudle/load_ui.py` 里的 `uic.loadUi(file, self)`
  改成 QUiLoader 子类（顶层控件复用 baseinstance + 按 name setattr），
  语义与 PyQt 的 `uic.loadUi` 对齐；路径 `common/tool/uic_compat.py` 有同款，
  但 App_LogPlot 要能独立跑，所以就地实现了一份。
- matplotlib：`backend_qt5agg`→`backend_qtagg`，`matplotlib.use('Qt5Agg')`→`'QtAgg'`。
- **QUiLoader 不调 setCentralWidget**，QMainWindow 的 .ui 要补（本项目 ui 都是
  QWidget/QDialog，暂时没踩到）。

**Qt6 严格枚举**（PyQt5 能吞 int/bool，PySide6 直接 TypeError）：
- `QCompleter.setCaseSensitivity(False)` → `Qt.CaseInsensitive`
- `QFont.setWeight(60)` → `QFont.DemiBold`（Qt6 刻度改成 100~900）
- 短名枚举（`Qt.AlignCenter`、`QSizePolicy.Expanding`）PySide6 仍可用，不必改。

**PySide6 额外报错**：同一 QObject 初始化两次会抛
`You can't initialize ... twice!`。`LogDataGenerator(IDataProvider, QObject)`
里 `QObject.__init__` + `IDataProvider.__init__`（后者 super() 又会走到 QObject）
就是这种，删掉显式那次、只留接口层调用即可（MRO：类→IDataProvider→ABC→QObject）。

**启动顺序坑（最关键）**：matplotlib 的 Qt 后端在 import 时若没有 qApp 会自己
造一个裸 QApplication，之后 `App(QApplication 子类)` 直接报
"Please destroy the QApplication singleton"。机器上装着 PyQt6 时它还会按
PyQt6→PyQt5→PySide6 抢绑定。处理：`log_plot_main.py` 顶部
`os.environ.setdefault("QT_API","pyside6")`（`app/plot_moudle/__init__.py` 里也有一份），
并把 `App_LogPlot.app.*` 的 import 从模块顶层挪进 `MainWidget.__init__`，
保证 `__main__` 先建 App。

**路径**：`rcd_tr.parse_tr_json` 原来用 `./cfg/ctu`，依赖 cwd；改成按
`__file__` 定位 App_LogPlot/cfg，入口放仓库根目录也能跑。

**原有缺陷（与 Qt 版本无关，本次只做兜底未修）**：
- `ui/rcd_plot.ui` 里没有 `pushButtonMultiLabels`，代码却连它的 clicked
  并改样式 → 加 `getattr(..., None)` 兜底，P 快捷键仍可用。
- `plotMatrixWithViceAxis.PlotMatrixWithVice` 是 `class ...: pass` 空壳，
  「组合图」按钮必崩（`takes no arguments`）。
- 图标 `datetime.png` / `grid.png` 缺失（QIcon 静默为空）。
- `log_plot_main.py` 的菜单信号接错：`关于`→导入文件、`导入文件`→版本说明。

**回归**：`tools/verify_log_plot_pyside6.py`（15 项：模块导入 / 选项卡 / 三个快捷键
开关 / 两个 QUiLoader 对话框 / QtXml 往返 / QCompleter / 样例 CSV 导入 16643 点 /
真实曲线绘制 / 播放线程启停），离屏跑全绿。

**环境**：`.venv` 里装了 App_LogPlot 的运行依赖（numpy/matplotlib/pandas/pyarrow/
pillow/jsonpath/Markdown）；venv 同时装着 PyQt6（历史遗留），所以 QT_API 必须钉死，
想省掉这层约束可以把 PyQt6 卸了。

## 业务层能否直接使用导出的 JSON（2026-11-06 上午）

**实测四种格式都能被 `load_tags()` 吃下**：
`globalvars_structure.json`（右键树导出，391 点）、
`globalvars_tags.json`（`--dump-mapping`，391 点）、
GUI 订阅映射、CLI `--json`（带 `struct_members`）。

但要分清两种「直接用」：
- `globalvars_tags.json` / GUI 订阅映射 / CLI `--json`：有 `nodes` 段，
  `mgr.subscribe(json.load(f)["nodes"])` 就能用。
- `globalvars_structure.json`：**没有 `nodes` 段**，不能直接喂 subscribe；
  但 `JsonTagClient(path)` / `load_tags()` 会从 `variables` 段重建映射，
  所以业务层用封装类时两份都能直接传路径。
- `struct_members` 无 NodeId，永远不能订阅。

**本轮补的缺口** `tools/opcua_from_json.py`：
- `JsonTagClient.start(subscribe=True, keys=None)`：加 `keys` 只订阅子集
  （PLC 对 monitored item 数量常有上限，391 个点一次全订阅不一定吃得消）。
- `read/write/read_many` 先 `_node_id(key)` 解析成 NodeId 再调管理器。
  **这是必须的**：`OpcUaManager._node_for_key()` 只在订阅表里查 key，
  未订阅的点直接把 `"velocity"` 当 NodeId 会 `BadNodeIdUnknown`。
  现在未订阅的点也能按 key 读写。

**回归**：`verify_opcua_from_json` 34 → **42/42**（新增 `[7]` 按需订阅：
只推订阅的 2 个点、未订阅点仍能读写并落到服务端）。
反向验证：去掉 `_node_id` 解析 → 4 项失败。
四套合计 91 / 34 / 74 / 42 全绿，编译与 GUI 离屏冒烟通过。

**给现场的边界**（回答里要讲清）：
endpoint 从 JSON 读、可用 `endpoint=` 覆盖；账号密码不在 JSON 里，
要走 `JsonTagClient(..., user=, password=)`；写入按 DataType 自动收敛，
但节点本身只读时仍会失败；`stop()` 必须调；`tag_changed` 的 key 就是
`nodes` 的语义 key（带数组下标）。

## 页面卡片改成「高4宽3」（2026-11-06 11:20 后）

用户要求 `高3宽4 → 高4宽3`，确认过是**场景卡片尺寸**（不是页面内控件网格）。

## 去掉滚动条 + 只刷新最前面两页（2026-11-06 11:40 后）

**需求**：不要滚动条；只更新最前面两页数据防卡顿。

**无滚动条**：`ScrollBody` 从 `QScrollArea` 换成
`QGraphicsView + QGraphicsScene + QGraphicsProxyWidget`（和
`EmbeddedWidgetLayer` 同一套）。内容按布局自然尺寸排一次，再用
`fitInView(sceneRect, KeepAspectRatio)` 整体等比缩放进视口，横竖滚动条
一律 `AlwaysOff`。信息不丢、不压扁重叠，代价是字号随比例变小
（1000×750 下 scale 0.564~0.992，轴页 0.627）。开了
`TextAntialiasing | SmoothPixmapTransform` 改善缩放后的文字。

**踩的坑（重要）**：
- 手写 `setTransform(scale)` 不行：QGraphicsView 仍按未缩放的 sceneRect
  做对齐/裁剪，右侧整片被切。必须用 `fitInView`。
- 构造期布局没 polish，`QLayout.minimumSize()` 接近 0（甚至是很小但非 0
  的值如 100×100），直接锁设计尺寸会退化成 320×240。解法：
  `content.ensurePolished()` + `vbox.activate()`，判据是
  `need.width() < MIN_DESIGN_W`（不能只判 `<=0`），不满足就
  `QTimer.singleShot(0, _sync_and_refit)` 最多重试 5 次；另外
  `resizeEvent` 每次都幂等校正一次、`HmiPage.showEvent` 再补一次。

## HMI 页面卡顿定位与优化（PopPick 7 页）

**测量工具**：`tools/profile_hmi.py`（`--idle` / `--stress old|new --rounds N` /
`--frames` / `--costs`）。压测场景必须在**独立进程**里各跑一次，上一轮的绘制
积压会算进下一轮间隔（实测把改造后也测出 1.2s 假尖峰）。

**根因（实测，不是推测）**
- 页面控件在 `QGraphicsProxyWidget` 里：**改一个标签就要重画整张页面**，且
  父窗口一脏，同一区域下**所有**承载视图都会被重画。7 卡全实时时一次刷新要
  重渲染 6 个视图。
- `PageHeader` 原来每页各挂一个 1s QTimer（共 7 个）。空闲时每秒触发 7 次整页
  重绘：事件循环 1s 只能跑 **2 轮**，`processEvents` 单次 1.9s。
- 推送逐点直刷控件 + `TagValue.set_value` 每次都 `setStyleSheet`（样式重新解析）。

**改法**
1. `PageHeader` 不再自带定时器；`HmiPagesHost` 用**一条** 1s 定时器只驱动
   **槽位页**。单页调试/预览用 `header.start_clock()`。
2. 推送合流：`_on_tag` 只入 `_pending`，100ms 一拍的 `_flush` 统一灌活跃页
   （`flush_ms` 可调）。同一轮事件循环里改完 → Qt 合并成一次重绘。
3. 控件级去重：`Lamp.set_state`、`TagValue.set_value` 值/颜色没变就 return。
4. **后台页静态化**：`HmiPagesHost.apply_static_pages()` 对非活跃页调
   `card.set_motion_cache(True)`（承载层自带的位图快照机制），进入前台再关掉。
   一次刷新从 6 个视图降到 2 个，CPU 65% → 14%，画面像素差 0.30/765。
   - **坑**：换完快照必须补一次 `scene._sync_embedded_widgets_geometry()`
     （`SceneManager.m_scene` 才是场景 widget），否则交换完成后切到前台那张卡
     的视图停在原地，画面上「换了页但内容还是另一页」。
   - 动画结束 `_set_fast_render(False)` 会把所有卡片的快照关掉 → 窗口接
     `deck.busy_changed` 在 busy=False 时重新 `apply_static_pages()`。

**效果**（离屏软件光栅，10Hz×20 点持续推）
| 指标 | 改造前 | 改造后 |
|---|---|---|
| 空闲重绘 | 7 次/s（每个视图 6 次/s） | 1 次/s |
| 事件循环 | 2 轮/s，单次 1.9s | 13 万轮/2s，空闲 0 重绘 |
| 10Hz 压测 | 10/30 次，最大间隔 1.3s，CPU 126% | 27/30 次，最大间隔 ~120ms，稳态 CPU 4~9% |
| 交换动画 | — | 29 帧/0.73s，中位 16.1ms（~60fps） |

第 1 轮 CPU 偏高（27~40%）是字体/样式一次性预热，第 2 轮起降到 9%/4%。

**回归**：compileall、`--verify`（363 key / 16 待接入）、`--attach`（7/7 挂载、
订阅 200 点）、交换 / 收起展开 / 换回、`--no-plc` 与默认启动全部通过。

## 7 页布局重做：固定 750×1000 画布、1:1 不缩放（2026-11-06 17:00 后）

**需求**：`所有页面都是（750，1000）的尺寸`。之前是「内容按 minimumSizeHint
排 → 整体等比缩放进视口」，同一张卡片下各页 scale 0.42~0.73，字号发糊。
现在改成**固定设计画布 + 1:1 呈现**，因此每页内部布局都得重排。

**画布口径**（`App_PopPick/hmi/widgets.py`）：
- `PAGE_SIZE = QSize(750, 1000)`、`HEADER_HEIGHT = 52`、
  `BODY_SIZE = 750×948`。

  content_minimum`；`_refit()` 里 `fitInView` 后若 scale 与 1.0 差 <1%
  或 >1.0，直接钉成 1.0（0.995 会让整页发虚）。
- 尺寸不匹配时不出滚动条、不缩放：超了就用 `overflow()` 报出来，改布局。
- `binding.PAGE_PIXEL_SIZE` 同步改成 `QSize(750, 1000)`：给 1000×750 控件，

**两个致命坑（都是这次挖出来的，必须记住）**：

1. **`QSizePolicy.Ignored` + `setMinimumWidth` 会让同行控件叠在一起。**
   `ElidedLabel` 原来用 Ignored 想"文字再长也不撑宽布局"，但 Ignored 让布局项
   的 `sizeHint()` 恒为 0，QBoxLayout 按 0 宽排位，`setGeometry` 又被控件
   最小宽度 clamp 上去 → 位置没变、尺寸变大，**叠**。表现是写入行整行只剩
   一个「速」：label 几何 64×48、hmiValue 却在 x=8、输入框 x=14。
   现在改成 `Preferred` + 自己覆写：
   `minimumSizeHint() = (minimumWidth(), fontHeight)`（长度不参与最小宽度）、
   `sizeHint() = 文字宽度 clamp 到 [minimumWidth, maximumWidth]`（端点/统计

   - Qt6 里对"当前行数之外"的行设 stretch 会被忽略，富余高度照样摊到第 0 行
     （9 行写入卡每行被拉到 36px）。改成真的塞一个
     `QSpacerItem(0,0,Minimum,Expanding)` 到 `_row` 行，才把空白留在卡片底部。

**其它已改**：
- 删掉 `TagValue` 的行分隔线 `_rule`：它画在控件底部，行被拉高时断成几段
  「小横杠」，纯噪音（现在行距由弹簧保证）。未接入点的 `--` 仍保留。

## 承载层「按住」语义：点动按钮按下即被判定为抬起（2026-11-06 17:30）

**现象**：鼠标按住 PopPick 页面上的点动按钮不放，业务侧立刻看到变量写 True
又马上写 False，像是"按下即抬起"。

**根因**：`EmbeddedWidgetLayer` 为兼顾"点控件/拖画布"对左键做延迟派发——
press 先扣住不转发，超阈值判为拖动画布，没超阈值才在 release 时补发
press+release。于是**按住期间控件根本收不到 press**，点动按钮
（`pressed`→写 True / `released`→写 False）只在松手那一帧背靠背发两次。

**修法**（`Designer/Core/embedded_widget_layer.py`）：
- 新增类属性 `PRESS_THROUGH_TYPES = (QAbstractButton, QAbstractItemView,
  QAbstractSlider, QAbstractSpinBox, QComboBox, QLineEdit, QPlainTextEdit,
  QTextEdit)`，外加 `getattr(child, "_clickable", False)` 覆盖自绘的可点灯。
- `eventFilter` 的 press 分支先调 `_press_through_target(pos)`：命中就
  `return False` 把整个手势交还视图（控件原生接管按下态/拖选/滚动）；
  命中页面根/卡片空白仍走延迟派发，画布照常能拖。
- 代价：按在这些控件上不能拖画布——本来就该如此。

**`_press_through_target` 的两个坑**：
1. `QWidget.childAt()` 只查子控件。直接承载的控件本身（比如整个卡就是一个
   QPushButton / QTextEdit）会返回 None，必须兜底 `child = widget`。
2. 向上遍历时别把 `child is not widget` 放进 `while` 条件——QTextEdit 的
   internal viewport 命中后，下一级正好是 widget 本身，条件先排除就漏检了。
   正确写法是循环体内先判断、再 `if child is widget: break`。

**回归**：
- 新增 `tools/verify_press_through.py`（7 项）：按住按钮 pressed 立即触发 +
  `isDown()` 保持 + 松手才 released；空白处仍扣住、仍能拖、点击不误触。
- `tools/verify_embedded_widget.py` 的 2c 段拆成两组断言：文本区按住直通
  且不平移画布 / 另建"容器+标签"承载层验证拖动平移与微动点击，现共 43 项。

### 补丁 v2：为什么 v1 没修好（2026-11-06 17:45）

v1 只加"按下点命中可交互控件就直通"，在真实 PopPick 页面上**完全失效**，
原因有两个，都要记住：

1. **HMI 页面是嵌套承载**：`HmiPage` → `ScrollBody(QGraphicsView)` →
   内层 proxy → 控件。按钮在**内层场景**里，`QWidget.childAt()` 的父子链
   走不到它 → `_press_through_target` 恒返回 None。
   修法：`PRESS_THROUGH_TYPES` 里加 `QGraphicsView`——按下点落在嵌套承载
   视图上就整块放行。

2. **PopPick 运行态本来就禁用平移**：`pop_pick_entry.py:289` 调
   `set_canvas_navigation_enabled(False)`。延迟派发唯一的用途是"拖动画布"，
   平移禁用后它只剩副作用。
   修法：`eventFilter` 开头加 `if not self._pan_enabled(): return False`
   （`_pan_enabled()` 读宿主 `is_pan_enabled()`，宿主没实现按允许处理）。
   顺带 `_start_pan` 也复用它。

**回归**：新增 `tools/verify_hmi_press.py`——把真实 axis 页嵌进承载层，
平移禁用 / 启用两种配置各跑一遍，断言：按住立刻 `pressed`、`isDown()` 保持、
按住移动 9px 不打断、松手才 `released`。加上 `tools/verify_press_through.py`
（合成结构）与 `tools/verify_embedded_widget.py`（43 项）全绿。

**排查提示**：改完 `Designer/Core/` 下的代码必须**重启程序**才生效；现象还在
时先确认进程是新的（日志时间 / 版本号），再怀疑逻辑。

## packTool.py（生成 spec 的 GUI 工具）扫描缺陷与改造（2026-11-06 21:20）

**证据**：`~/.python_packager_spec_config.json` 里
`hidden_imports=["asyncua"]`、`resources=[res, snap7.dll]`，与上一轮那个缺库
spec 完全一致；`build/temp_工具集` 正是工具生成的 `temp_工具集.spec` 的
workpath。**我手工修好的 `工具集.spec` 下次点「保存 Spec 文件」会被覆盖回缺库版**，
所以必须改工具本身。

### 原来的「扫描」其实是零
只有 `glob("*.py")` 找 main.py；隐藏导入、资源全靠手填。PyInstaller 静态分析
看不到的东西，工具一样看不到。

### 逐条缺陷（都已修）
1. **`shutil.which('pyinstaller')` 优先于 `sys.executable`** —— 上一轮事故的直接
   原因。PyInstaller 只看自己所在解释器的 site-packages，PATH 指到
   `D:/rack/rack_config/.venv` 就静默缺库。现在 UI 新增「Python 解释器」，
   命令固定 `[python_exe, "-m", "PyInstaller", ...]`。
2. **返回值 0 就报「打包成功」**，从不读 `build/<spec>/warn-*.txt`。
   hiddenimport 找不到时 PyInstaller 只写 warn。现在打包后扫 warn，
   声明过的隐藏导入缺失 → 直接判失败并列出来。
3. **依赖检查形同虚设**：`_start_packaging` 里 `import PyInstaller` 查的是 GUI
   自己的解释器，跟打包用的解释器不是一回事。现在用 `subprocess -c` 在
   **指定解释器**里 `find_spec` 检查；生成的 spec 里也带一份自检。
4. **隐藏导入只写顶层包名**：现在生成 `collect_submodules`（asyncua 112 个），
   UI 有开关，默认开。
5. **资源没有「包内目标目录」概念**：一律保持层级。RCD 的
   `plot_moudle/{ui,cfg,ico,data}` 需要摊平，`App_PopPick/hmi/data` 需要保持层级，
   两者冲突。现在添加资源时弹窗问目标、双击列表项可改，配置里存
   `resource_dests`。
6. **两个死控件**：「输出目录」和「附加参数」只写进 UI / spec 注释，命令里没带。
   现在 `--distpath` 和 `shlex.split` 后的参数真正拼进 cmd。
7. **预览里编辑的 spec 会被丢弃**：`_preview_spec` 只弹个提示，保存/打包又重新
   生成。现在缓存 `_edited_spec`，保存和打包都优先用它。
8. **临时 spec 失败也删**，没法复盘；现在只在成功时删。
9. 其它：路径写死本机 → `ROOT = Path(SPECPATH).resolve()`；字符串直接 f-string
