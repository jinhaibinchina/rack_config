## Stage 2 可评审方案（只写文档，未改生产代码）

产出 `docs/stage2_geometry_backend_design.md`（538 行，评审稿）。核心是**修正了上一轮给 Stage 2 的收益口径**，三条硬事实：

1. **四叉树被显式禁止用于可见性判断**：`myGraphicsScene.py:1534-1549` 注释写明运行态图元会动、树记录不总是最新；`refresh_dynamic_buffer` 本来就是全量遍历 `m_sorted_items` + `sceneBoundingRect().intersects()`。所以 C 侧「可见 id 列表」必须来自**全量 bbox 数组线性扫描**，不能来自空间索引；四叉树只服务交互查询。L1/L2/L3 三层剔除 + `set_dirty_region` 对全部图元调用，都要原样保留。
2. **「状态层单一真值」在当前工作树不存在**：`rack_stores_status_model.py` 已被 `commit 14a377d` 删除，`App_RackConfig/run/__init__.py:34-52` 留 6 个悬空 `__all__` 名；`RackStoresWindow.refresh_models()`、`HmiPagesHost.refit_cards()`、`QuadTreeScene.initialize_event_handlers()` 全是死代码无调用者。真值实际散在图元对象上 → C 数组只能是派生存档，**失效协议是方案成败关键**，不是附属细节。
3. **5~6 ms 达不到**：只读几何后端确定性收益约 1.2 ms/帧（bbox 剔除 1.07 → <0.05 ms），推算合计 2.7~4.7 ms，帧落 **6.5~8.5 ms**；逼近 4~5 ms 必须整段绘制循环进 C++（P3）或路线 C。

补充探针实测（临时脚本跑完已删）：1618 项中 rect 1205 / circle 192 / text 103 / group 96；一帧全屏 44165 次调用，其中 `sceneTransform`+`itemTransform` 各 3705 次、`QPointF.x/y` 各 5561 次、只有 **417 项**真正进 paint、`setPen/save/restore` 各 407 次；L1 全屏已剔除 74%（417/1618），400×300 → 60 项、200×200 → 34 项、50×50 → 14 项；quadtree 全屏 0.456 ms vs 全量扫描 1.985 ms。所以瓶颈是「417 个图元内部平均 9 次变换链 + 407 次 QPainter 状态切换」，不是遍历 1618 个对象。

**方案要点**：SoA 连续 double 数组（slot 稠密下标，与 item.id 解耦）；推荐 **纯 C DLL + ctypes**（不 include Python.h/Qt 头，不引入编译依赖、不受 PySide6 的 MSVC 1943 ABI 锁定、`requirements.txt` 不动），pybind11/.pyd 仅在决定做 P3 时才需要；**bbox 不搬 C**（7 套公式 + paint 末尾 `__check_position_change()` 兜底重算无法预测），改为 Python 每帧单向回灌 52 KB；影子对拍 + MISMATCH 自动退回 `RACK_GEOM_BACKEND=0`；写闸门收敛到 `invalidate_transform_cache` / `update_boundingRect` / `completed` 三个公共收口 + 7 类原地修改点补钩子。

分阶段 P0 影子层（不可跳过，1000 帧 fuzz 零 MISMATCH）→ P1 变换/剔除接管 → P2 交互索引 → P3 批量绘制**建议暂缓**（与并行的 C++/Qt6 HMI 重复）。6 个待拍板决策点 D1~D6。打包注意 `packTool.py:1010` 把 `binaries=[]` 写死、`工具集.spec:159` 需加 DLL、`verify_pack_tool.py` 有多处断言要同步。

## 路线 C（原生 QGraphicsScene）归属澄清 + 收益实测

用户追问「迁原生 QGraphicsScene 指 Python 还是 C++、能提升多少」。概念结论：**QGraphicsScene/QGraphicsView/BSP/脏区/裁剪永远是 Qt6 C++ 实现，PySide6 只是绑定，不存在 Python 版**；差别只在图元层 —— 用内置 `QGraphicsRectItem` 等是 C++，自定义 `QGraphicsItem.paint/boundingRect` 覆写仍是 Python，而 `boundingRect` 用 Python 会让 BSP 查询每次回调 Python。真正「全 C++」是并行的 C++/Qt6 HMI（C3）。

新增 `tools/bench_qgraphics_scene.py`（323 行，4 个 phase：`dump` 导出 page_1 的 1618 个视图坐标 bbox → `build/qgs_rects.json`；`self` 自绘分项；`qgs` QGS 分项；`ab` 同进程交错，**结论以 ab 为准**；3 个 kind：`native`/`pypaint`/`cache`）。

**口径坑（重要）**：跨进程绝对值实测波动可达 **2×**（同一命令全屏 5.56 ms → 11.41 ms，纯 CPU 调频），不能当承诺值；必须同进程交错 A/B 取比值，并在每轮附测固定 `drawRects` 地板确认漂移（三轮地板 2.72~2.75 ms 稳定）。

同进程 A/B（QGS/自绘，min-of-20）：全屏 1440×900 **native 33.7% / pypaint 46.0% / cache 68.3%**；中 400×300 15.3% / 36.8% / 18.0%；小 240×180 16.4% / 27.5% / 10.5%；微 80×60 10.1% / 23.6% / 7.6%。BSP 命中 item 数 396/43/25/10。分项绝对值：线性命中 1.165 → BSP 0.121 ms（`pypaint` 退化到 0.423）；移动 1 项后重绘 0.685 ms（索引维护几乎免费）；`DeviceCoordinateCache` 全屏首次更贵、只适合长期静态 + 小脏区。

结论：路线 C 的价值**不在全屏峰值**（与 Stage 2 P1 的 6.5~8.5 ms 目标重叠，且要重写图元模型），而在**小脏区增量刷新与命中查询（4~10 倍）**；自绘微脏区仍有约 1.2~2.1 ms 固定成本，来自全量遍历 `set_dirty_region`+`sceneBoundingRect`，Stage 2 P1 拿不到这一段。另修正文档 §1 末尾「逼近 4~5 ms 需路线 C」—— 原生 item 全屏 3.5~5.6 ms 已是理想下限且未含真实图元复杂度，4~5 ms 达不到。

文档补 **附录 C**（`docs/stage2_geometry_backend_design.md` 538 → 594 行）：归属表、口径、A/B 数据表、收益拆解、兑现折扣与陷阱、对 §1 结论的修正。本轮只新增脚本 + 文档 + 日志，生产代码零改动；`page_*.json` 仍保持用户会话前就有的未提交状态，未动。

## 新增 Designer/CoreQGraphics（QGraphicsScene 平行实现，核心可运行闭环）

用户确认范围＝「核心可运行闭环」（场景 + 12 类图元 + page 读写 + 选中/移动/缩放/旋转/吸附/分组 + 对拍），不含属性面板、工具箱、PLC、嵌入式控件运行时。新增 8 个文件 1460 行 + `tools/verify_core_qgraphics.py` 242 行，读同一份 `page_*.json`、序列化格式零改动，**不改 Designer/Core 任何代码**。

**三条架构决策（都有代码事实支撑）**：
1. **坐标系用「投影后的视图坐标」**：Core 的 `sceneToView` 是 AGV 轴交换 + 双轴取反（det<0），`M·R(a)=R(-a)·M`，所以加载时把几何投影、旋转角取负，交给 QGraphicsItem 后 `sceneBoundingRect()` 精确等于旧 `viewBoundingRect()`，`page_bounding_rect()` 反投影后精确等于旧 `sceneBoundingRect()`（AABB 与 M 可交换，rotate≠0 也成立）。这样文字不会被整体镜像 transform 翻转。
2. **所有 item 在 Qt 层平铺，绝不用 setParentItem**：旧实现按 zValue 稳定排序，page_1 有 1411 个重复 zValue 靠 JSON 顺序定层级；Qt 父 item 的 z 会把整组拉到一起。分组只在 `SceneIndex` 里做 `parent_id` 逻辑映射，移动组时 `on_item_moved` 按 delta 联动后代。
3. **未编辑的 item 回写原始 dict 深拷贝**，保证 round-trip 零改动；编辑后从 Qt 几何反投影回写。

**实测（`tools/verify_core_qgraphics.py`，26 项全过）**：1618/1618 图元的 `sceneBoundingRect()` 与 `viewBoundingRect()` 双双逐项相等（容差 1e-4）、zValue 排序 id 序列完全一致、类型映射 1618/1618、page JSON 逐条结构零改动、两次 render 逐像素一致、交互与 T 门控吸附全过。`verify_scene_fast` / `verify_render` 既有回归也全过。截图 `build/core_qg.png`（离屏缺中文字体，文字显示为方块，非渲染错误）。

**踩过的三个坑（重要）**：
- `g_style.pen_for()` 里 `int(Qt.SolidLine)` 在 PySide6 6.10 抛 `TypeError`（PenStyle 枚举不能 int）；异常发生在 `QGraphicsScene.render()` 的 C++ 绘制回调里**不会传播，直接变成 access violation / exit=139**。排查手法：`faulthandler.enable()` + 逐类型 stub paint + trace item id + 最小复现逐句执行。修法：枚举本身可哈希，直接放进缓存 key。
- `BaseItem.__init__` 的 `setPos/setRotation` 会触发 `itemChange` 误标 `_dirty`，导致 round-trip 重算坐标；修法：`itemChange` 里先判 `self.scene() is not None`。
- triangle/polygon 的 JSON `vertices` 是**已烘焙 rotate 的场景绝对顶点**（Core 的 `_apply_scene_vertices` 把 angle 折进局部顶点，`get_scene_vertices()` 又还原），绝不能再旋转一次；只有 rotate=-27.5 的 polygon 1660/1662 会暴露这个错。

**边界**：widget 只画占位框 + "Widget" 字样，不创建 EmbeddedWidgetLayer；`origin_pos != center_pos` 未复刻独立旋转支点（page_1 的 1618 条两者全相等）；无属性面板/工具箱/导航/PLC/料仓绑定。**12 类 paint 全部仍在 Python**，所以帧耗时与自绘同量级，上一轮 -54%~-66% 要换 Qt 内置 item 或 C++ paint 才兑现；验证脚本第 4~6 节会改场景状态，故不在其中采样性能，改指向 `tools/bench_qgraphics_scene.py --phase ab`。

- `ui/design_window.py`：工具箱 `toolActivated`、工具栏「绘制」按钮、菜单「新建图元」全部改为调用 `_activate_draw_tool(type)`（进入绘制模式并给状态栏提示），删除原 `_create_at_center`；新增 `_on_draw`：非拖拽→默认尺寸落到点击点，拖拽→`QRectF(start,cur).normalized()` 经 `projection.inverse_point`/`inverse_size` 换算成 page 的 center/size，再 `scene.create_item` + 选中 + `_after_edit`（含历史提交）；`run_mode` 切换时 `view.set_draw_tool(None)`。

## 父对象刚体位姿传播 + 右键指定旋转中心（CoreQGraphics）
- 需求：①父对象平移/旋转时子图元中心跟着动；②有父对象的图元位姿只能由父对象决定；③旋转中心可用鼠标右键指定。
- **Qt 变换原点的真实语义（关键，反直觉）**：`scene(q) = pos + o + R·(q - o)`（`o = transformOriginPoint`），即「先绕局部点 o 转、再平移 pos」；`pos` 不是支点。且**角度为 0 时 Qt 完全忽略 o**（支点只能靠 `_origin_xy` 维护，反读不出来）。由此解出 `_place()`：`o = R⁻¹(point(O)-point(C))`、`pos = point(O) - o`；O==C 时退化成 `o=0, pos=point(C)`（存量页面零变化）。
- **旧实现是真 bug**：旧 `_apply_transform_origin` 用 `o = point(O)-point(C)`（漏 R⁻¹）且 `pos = point(C)`，导致 `origin≠center` 且有旋转的图元整体偏移。用 `verify_core_qgraphics.py` 的加载器对拍 page_9/7/10：旧公式 5/7、5/12、5/7 项几何不符，新公式 **0 项差异**（page_3/10 也是 0）。现在 CoreQGraphics 与 `Designer.Core` 在这些页面上逐图元 bbox 完全一致。
- 传播（`g_scene.on_item_moved`）：用「中心 + 角度」就够——`p' = R(dA)(p - C_old) + C_new`。支点不参与 delta，所以「只改支点（中心不动）」不会误当成平移。`_last_pos` 改成 `_last_pose`（存 `(cx, cy, angle)`），全部从 `live_page_pose()` 反读。
- **踩坑：`setRotation` 只发 `ItemRotationHasChanged`，不发 `ItemTransformHasChanged`**（`setPos` 才发 `ItemPositionHasChanged`）。`BaseItem.itemChange` 必须把 `ItemRotationHasChanged` 也接上，否则父对象旋转不触发传播。
- 顶点类图元（line/triangle/polygon/path）不能靠 Qt 旋转（rotate 已在 vertices 里烘焙）：`_PointBasedItem.apply_rigid_pose` 把旋转烘焙进顶点，Line 走 `set_page_head_end`，Path 保留 `move` 分段标记后 `_build_path()` 重建。
- 位姿锁：`pose_locked()` = `parent_id != 0`，`set_page_center`/`set_page_angle`/`rotate_by` 直接拒绝；`refresh_movable` 不给子图元 `ItemIsMovable`；属性面板布局页禁用中心/角度三个 spinbox。拖动子图元 → `GraphicsView._child_root_under()` 改成拖**根父对象**（`_proxy_drag` 手工拖，选中根父 + 状态栏提示），否则「拖不动」像卡死。吸附 `_apply_snap_to_selection` 也跳过子图元。
- 右键指定支点：`mousePressEvent` 记录右键处的 page 坐标 `_context_page`；菜单加「旋转中心设到此处 / 复位到图元中心」→ `actionTriggered` → `_do("origin_here"/"origin_center")` → `scene.set_selected_origin/reset_selected_origin`。选中时画蓝色十字圆环 + 中心→支点虚线（`_draw_origin_markers`，固定屏幕像素，只在自定义支点时画）。
- `rotate_by` 语义保持**视图角度**（`page_angle - delta`，因为投影镜像 `angle()==-a`），否则 [ ] 快捷键转向反了（引擎对拍脚本会挂）。
- 顺带修：拖拽只改 Qt 变换不走 `notify_edit` → 页面从不标脏，关窗静默丢改动。现在 `on_item_moved` 外部平移时置 `_modified`，视图松手发 `actionTriggered("drag_done")` → `_after_edit()` 记撤销（撤销能同时还原根父和子图元）。
- 回归：`verify_core_qgraphics_ui.py` 新增 §8.11（刚体传播，含孙级/顶点类/支点跟随）、§8.12（位姿锁 + 面板禁用 + 拖子图元转拖根父）、§8.13（右键支点落到点击处 + 蓝色标记像素 + 绕支点转 + 复位）；引擎与 UI 两套均 **失败 0 项**，`verify_property_panel` 全通过。§8.9 因为属性面板多了一行提示导致底部 Dock 重新布局（视口高度 528→515，AnchorViewCenter 平移画面），断言前要重取 `vp`。

## 位姿锁拆成「只锁平移」+ 父坐标系 + 标识画到支点（同日第二轮）

## 背景网格 + 网格交汇点吸附 + 鼠标偏移驱动图元（同日第三轮）

参考 `Designer/Core/myGraphicsScene.draw_grid` 与 `Core/mySnapSystem` 的两处关键做法（网格步长固定、网格点解析计算、图元点优先级、吸附后同步鼠标基准）。

- **网格**：`g_snap.SnapSystem` 新增 `grid_step` / `grid_origin` / `grid_enabled` / `hover`；`g_view.drawBackground` 改走 `_draw_grid()`，步长与捕捉共用同一个 `grid_step`（不共用就会出现「看到的格子和能吸的格子不一致」）。`adapt_grid_to_scale(scale)` 按 2 的幂细分/合并，保证屏幕格宽落在 `18~90 px`。锚点 = `projection.point(0,0)`（AGV 下即旧 Core 的 `sceneToView(0,0)`）。菜单「显示网格」默认勾上，`_do("toggle_grid")` 同时同步 `snap.grid_enabled`。
- **网格点不枚举**：`nearest_grid()` 直接 `round((p-origin)/step)`，同 Core `get_nearest_grid_point`；`aim()` 里图元点先比、网格**严格更近**才顶替（同 `snap_to_point` 的顺序）。端点/中点改存**空间哈希**（cell 64），`_nearest_indexed` / `candidates` 只扫光标附近格子——page_1 有 14544 个点，线性扫描会让鼠标每帧遍历两遍；索引后 hover+aim+candidates 实测 **0.017 ms/帧**（原线性扫描未测完就明显拖手）。
- **鼠标附近标记**：`_draw_hover_snap_points()` 只画阈值 1.6 倍内的候选点（橙色细十字），当前命中点加粗 + 圆环；`_set_hover()` 只重绘新旧两小块 96×96。原来「T 打开时全屏画红色十字」被替换。**标记颜色必须避开 (214,51,46) 红与 (22,119,255) 蓝**：最初用红 (230,60,50)，命中 `_is_dot` 判据，把 `中心点标识不再画在几何中心` 这条断言误判成失败；改橙 (255,150,0) 解决。
- **吸附基准从「包围盒中心」改成「鼠标位置」**：`_apply_snap_follow()` 算 `offset = target - hover`，把 `offset - _snap_offset` 的增量 `moveBy` 给选中的无父图元 → 鼠标吸了多少，图元就移动多少，多选同量平移。`_snap_offset` 记「已叠加量」，所以原地重复按 T、T 关再开都不会重复推（这是 Core `move_item_to_snap_pos` 里同步 `sence_pos_mouse_save` 的等价物）。`allow_release=False` 给 T 键（鼠标没指到任何点时不回退已吸的偏移）。
- **拖动中不要 moveBy**：Qt 对可拖图元用「按下点 + 鼠标位移」的**绝对**定位，每帧 `mouseMoveEvent` 会覆盖我们叠加的偏移（实测只剩 0.059 / 期望 1.35），看起来像吸不动。改成拖动中只显示标记、**松手时补一次**；T 键不受影响（非拖动）。`_items_moved_since_press()` 用按下时的位置判断「这次到底有没有真的拖动」，没拖动就不吸——否则「未按 CTRL 拖不动」的契约会被吸附绕过去（`require_movable=True` 是第二道闸）。
- **T 键吸附要记撤销**：`_apply_snap_follow` 返回 True 时 `actionTriggered.emit("drag_done")` → 主窗口 `_after_edit()`；拖动路径仍由 `_notify_drag_done()` 负责。
- **阈值按屏幕像素**：`pixel_threshold = 12px`，`_sync_view_metrics()` 在 `setScene` / `fit_*` / `wheelEvent` / `resizeEvent` 里换算成场景单位（`threshold = 12 / scale`）；放大到 1:1 附近是 12 场景单位，整页缩放（scale 0.118）会变成 101，正好覆盖半个格子。
- 回归：引擎 `§6` 显式 `grid_enabled=False` 只测端点/中点（否则「吸附到最近标记」会因网格点更近而变成测网格），另加网格四问（解析计算 / 不进点集 / 可作捕捉点 / 步长自适应）；UI 新增 `§8.15`（默认开网格、步长屏幕口径、格点严格对齐、未枚举、网格可吸、端点优先、候选只在附近、橙色标记像素、T 吸附位移 == 鼠标偏移、重复开关 T 不漂移、拖动松手位移 = 鼠标位移 + 吸附偏移、多选同步）。两套均 **失败 0 项**，`verify_property_panel` / `verify_box_select` / `verify_render` / `verify_run_selection` 全通过。

## 各类型布局页对齐矩形 + 光标处只剩一个捕捉点（同日第四轮）

用户口径：「其他图元的属性-布局页面参考矩形实现，应该只显示最近的一个捕捉点十字标识，按下 t 鼠标能吸附过去」。

- **顶点类支点默认值原来是错的**（真 bug）：`_origin_xy` 在 `BaseItem.__init__` 里从 `origin_pos` 读，而 line/triangle/polygon/path 的**中心是顶点算出来的**，构造时还拿不到 → 新建图元的支点停在 (0,0) 或第一个落点。后果：布局页「旋转中心」读数错（矩形显示中心、多边形显示首点），`set_page_angle(30)` 后中心飞到画布外（实测 line 中心 (910,880) → (351,1212)）。
- 修法：`BaseItem._pivot_is_default()`（支点 ≈ 可视中心）+ `_rebase_pivot(old, new)`（默认支点跟到新中心；自定义支点按中心位移整体平移，不再被宽高/顶点编辑冲掉）。接到 `_PointBasedItem.set_page_vertices`、`LineItem.set_page_head_end`、`PathItem.set_page_vertices` / `_build_path`。`apply_rigid_pose` 里自定义支点要**刚体变换**（rotate 而不是 translate），所以那里先 `custom = not _pivot_is_default()` 再 `rebase_pivot=not custom`，末尾单独写回。
- **重建期间必须 `_suppress_geo = True`**：`_setup_vertices` / `_build_path` 里的 `setPos` 会触发 `on_item_moved`，它拿 `_last_pose` 的旧中心做差分 → 纯平移分支会 `shift_origin_by`，把刚设好的默认支点又推到包围盒角落（实测三角/多边形支点变成 (max_x, max_y)）。加抑制后 `_last_pose` 仍会在 `on_item_moved` 顶部刷新，所以下一次真实拖动不受影响。
- `PathItem._build_path(vertices, rebase_pivot=True, old_center=None)`：`old_center` 必须**在改写 `center_pos` 之前**取；`set_page_vertices` 直接改记录，所以由调用方传进来（否则 `page_center()` 读到的已是新值，判不出「原来是不是默认支点」）。
- **捕捉点只留最近的一个**：`SnapSystem.aim(point, exclude, always=False)` 新增 `always`。`always=True` 时阈值内没有端点/中点就退到**最近的格子交汇点**（格点解析算，永远存在；网格关掉时放宽到 4× 阈值的图元点）。`_hover_marker()` 与 `_apply_snap_follow()` 都走 `always=True` → 光标附近**始终恰好一个**橙十字，且按 T / 松手一定吸得动（以前光标在大图元内部时，自己的点被 `_selection_own_points()` 排除，附近又没别人的点，就既没标记也按 T 没反应）。
- T 键补两条：`snap.hover` 被 `leaveEvent` 清空时退回 `_last_hover`（点过属性面板再按 T 也生效）；只在 `viewport().underMouse()` 时才 `_warp_cursor_to_snap()`，避免把系统光标从别的窗口劫走。
- 注意：`always=True` 让**松手也按最近格点吸附**（最多半格）。吸附是 T 门控的开关，不想要就再按 T 关掉。
- 已知遗留（未改）：顶点类改角度后 `to_page_record` 会把旋转**立即烘焙进顶点**并把 `rotate` 归零，所以「旋转」输入框重新选中时读回 0（形状是对的）。要让读数和矩形一致得改成「只在存盘时烘焙」，会牵动撤销快照与 §8.11/§8.12 的口径，暂未动。
- 回归：UI 新增 `§8.16`（7 种类型布局页 7 个输入框全可编辑、旋转中心默认=几何中心、默认支点旋转不挪中心；远端光标 strict=None 但 marker 唯一、按 T 位移 == target-hover）。引擎/UI 两套 **失败 0 项**，`verify_property_panel` / `verify_box_select` / `verify_render` / `verify_run_selection` 全通过；page_1 逐图元对拍仍 0/1618、round-trip 零改动。
- 真实页面：料架9（153 后代）转 8° 24 ms；多边形 1655 自转 20° 中心漂移 5e-4（顶点 3 位小数取整）。截图 `build/layout_polygon_snap.png`。

## 顶点类旋转：支点不漂移 + 绝对角度可反复设（同日第五轮）

用户口径：「多边形和三角形旋转有问题，旋转中心会偏移」。

- **根因**：顶点类的「中心」原本是**烘焙后顶点的包围盒中心**。三角形不是中心对称图形，绕中心转 30° 后包围盒中心必然换了个空间点（实测中心 (200,180) → (200,130)，支点跟着跳 50）。`set_page_vertices` 又用 `_rebase_pivot(old, new)` 把默认支点顶到新包围盒中心 → 转一次支点跳一次，再转就绕错点转。矩形/线/矩形多边形是中心对称的，所以只有三角形和任意多边形暴露。
- **修法**：烘焙是**纯记账**（顶点一个都不动），中心与支点必须由调用方原样带过去。`set_page_vertices` / `PathItem._replace_points` / `LineItem.set_page_head_end` 新增 `center=` / `pivot=` 关键字：传了就按传入值落（旋转烘焙、父级刚体、缩放都传），都不传才是「新形状」口径（中心=包围盒中心 + `_rebase_pivot`，绘制落子走这条）。`_setup_vertices(vertices, angle, center=None)` / `_build_path(vertices, center=None)` 支持指定局部原点。
- **`_baked_angle`**（顶点类新状态）：几何烘焙进顶点后 Qt 旋转恒为 0，`rotation()` 读不出朝向，属性面板「旋转」框会归零、再输绝对值就变成叠加（30 → 60 实际转 90）。改成 `page_angle() = _baked_angle - rotation()`，`_turn_to` 按 `page_angle()` 求增量、给 `_apply_pose` 传残量 `angle - _baked_angle`（矩形类 `_baked_angle` 恒 0，行为逐位不变）。烘焙时 `_baked_angle -= rotation()`；父级刚体时 `_account_bake(dangle)` = `_baked_angle - rotation() + dangle`（待烘焙旋转会一起折进顶点）；缩放（`set_page_size`）也按总角度重新记账。
- **落盘口径**：顶点类的 `rotate` 现在存「已烘焙的真实朝向」（`_PointBasedItem.to_page_record` 只在值不同才覆盖，未编辑图元仍原样回写）。旧 Core 的 `_apply_scene_vertices` 是「先按 angle 反旋到局部、再按 angle 正旋画」= 恒等，所以存真角度安全，不会二次旋转（§8.11 新增 reload 后包围盒不变断言）。
- **`pivot_scene_point()` 改成投影 `page_origin()`**，不再 `mapToScene(transformOriginPoint())`：顶点类烘焙后 Qt 旋转归零、变换原点被重置成 (0,0)，映射出来是中心而不是支点。`g_view._draw_origin_markers` 相应改用 `has_custom_origin()`（新入口，= `not _pivot_is_default()`）。顺手放开 `set_selected_origin` / `reset_selected_origin` 对顶点类的限制（以前只对 `has_explicit_geometry()` 生效，右键设支点对三角/多边形无效）。
- **`_suppress_propagate`**（`on_item_moved` 里判）：烘焙重建会 `setRotation(0)`，位姿差分看起来像「转了 -θ」，会把后代反向带一遍。烘焙期置 True 后只刷新 `_last_pose` 不传播。
- 宽高口径顺带修正：`page_size()` 现在按总角度反旋，旋转后仍报自身尺寸（200×160 不会变成 253×139）；`set_page_size` 的缩放基准从包围盒中心改成可视中心，改宽高不再挪中心/支点。
- 回归：UI 新增 `§8.17`（三角/多边形/线/路径 反复设 30→60→90→30→0 后中心与支点漂移 < 1e-6、角度读回设定值、宽高不变、自定义支点钉死；面板连续两次设绝对角度 = 60 不是 90，且中心/支点不动），`§8.11` 改判「Qt 旋转归零 + rotate 记真实朝向 + 重载不二次旋转」。引擎/UI 两套 **失败 0 项**，page_1 逐图元对拍仍 0/1618、round-trip 零改动；探针 `tools/probe_point_rotate.py`（顶点级旋转数学 + 存盘重载）全通过。
- 已知遗留：顶点记录保留 3 位小数，反复烘焙有丝级累积（5 次 < 0.01 场景单位）；宽高读「自身尺寸」依赖 `rotate` 字段，旧页面（page_3 三角形 rotate=92.5）读出来的宽高会变成真实自身尺寸而不是旋转后包围盒。
