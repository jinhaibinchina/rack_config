## 文本图元：属性面板改字号 + 边框背景随文字计算（CoreQGraphics）

## 文本图元：改边框反算字号（双向联动，CoreQGraphics）

用户回复「接着补」，承接上节末尾提出的「拖角/改 W/H 时反算字号，像旧 `change_size` 那样」。

### 旧 Core 精确口径（只读核实）
- `text_element.calc_font_size(target_height, text)`（elements.py:2906）：建 QPixmap/QPainter，`size` 从 1 试到 499，取 `boundingRect().height() <= target_height` 的最大字号，返回该字号下文字**宽度**。
- `text_element.change_size(w,h)`（:3188）：`text_height_view = self.width * grid_size / scene_units_per_grid_x` → `calc_font_size` → `self.height = 文字宽度 * units_x / grid_size`，即**宽度驱动字号、高度由文字派生**；之后才按 `_resize_anchor_local` + `_axis_scale` 重算头点/中心。

### 实现（反向：边框 → 字号）
- `g_element.py`：`__init__` 加 `_text_resizing`（双向互斥标志）；新增 `_on_size_changed(w,h)` 空 hook，在 `set_page_size()` 与 `resize_by()` 成功路径末尾调用；`_sync_field` 的 style 分支在 `_text_resizing` 时跳过 `_on_text_changed`。
- `g_elements.py` `TextItem`：`_on_text_changed` 用 `_text_resizing` 包住 `set_page_size`（防止刚设的字号被反算覆盖）；新增 `_on_size_changed` + `_fit_font_size`（二分 4~200 找两轴都装得下的最大整数字号，等价于 `calc_font_size` 但避免 1..500 线性扫描）；**只写 `style.font_size`，不改 W/H**——派生高度会让拖角每帧增量比例抖动、组子树仿射失真。
- `ui/property_panel.py`：`refresh_geometry` 把反算字号回显到「文本内容」/「外观」两处 `_font_boxes`（blockSignals）；布局页对文本图元加 hint 说明两轴口径。
- `BaseItem.resize_by` 顺带修复既有缺陷：原先只改 `_w_view/_h_view` 不写 `_page`，导致 `page_size()`（面板显示 / 后续 `set_page_size` 基准）与实际几何差一个 factor；现在同步写回 width/height 或 radius_w/h（`to_page_record` 的 `_geo_dirty` 重建用同组值，存盘不变）。
- **加载 / 撤销走 `_setup_rect` 构造路径，不经过 `set_page_size`**，所以两个方向都不会污染存量记录。

### 关键口径
- AGV 轴交换：`proj.size(w,h)=(h·ky, w·kx)`，即 page W→view 高（行高方向）、page H→view 宽（文字长度方向）。`_fit_font_size` 取两轴 min 约束，因此**缩小任一轴都会收紧约束让字号变小（这正是防裁字）**，只放大一个轴受另一轴限制字号不变；拖角 / 组缩放 / `+/-` 两轴同变，字号联动且可逆。
- 实测：贴合 fs40 → W/H×2 得 fs81 且文字仍装得下 → W/H÷2 得 fs16；组 ×2 子文本 24→51，再拖角 ×0.5 回到 24；显式改字号 33 不被反算覆盖。
- 与旧 Core 的差异如实保留：旧 Core 会由文字宽度派生 height，新场景保留用户给定 W/H；两处设计器互开时字号仍不完全等价。

## 位姿「乱掉 / 跑飞」的根因：`scenePos()` 不能当平移基准（两处已修）

### 根因
图元有**自定义支点**（`origin_pos ≠ 中心`）且旋转非 0 时，
`scenePos() = pos + (o - R·o)`，与 `pos()` 恒定差一个「绕支点那一转」的定长位移 `e`。
任何 `setPos(读来的位置 + delta)` 的写法，只要读的是 `scenePos()`，每帧都会白走 `e`：
鼠标不动图元也漂，实际拖动几帧就飞出画布。**正放时 R=I → e=0，所以只有斜图元暴露**，
这也是「记录值全部自洽、只有屏幕上的位置乱」的由来。

### 两处修复
1. `Designer/CoreQGraphics/g_element.py:757` `set_page_center()`
   `self.setPos(self.pos() + delta)`（原 `scenePos()`）。
   实测 Page6（29°）交换时中心偏 2616px，修复后 <0.5px。
2. `Designer/CoreQGraphics/g_view.py:466` 拖动子图元代理分支

## 跟手状态下的滚轮缩放（CoreQGraphics/g_view.py）

不动图元几何。锚点残差降到 <1 场景单位（滚动条整像素取整，屏幕上 <1px）。
