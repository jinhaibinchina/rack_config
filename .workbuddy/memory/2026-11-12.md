## 修复 `App_test_fixture/__main__.py` 脚本方式启动崩溃

现象：`python App_test_fixture/__main__.py` 直接报
```
usage: __main__.py [-h] [--source ...]
__main__.py: error: unrecognized arguments: - - s o u r c e   m o d b u s
```
退出码 2。

根因：文件末尾写成 `main("--source modbus")`，但 `fixture_app.main(argv)` 收的是
**参数列表**（`parser.parse_args(argv)`）。传 `str` 会被 argparse 当 `Sequence[str]`
逐字符迭代，拆成 `- - s o u r c e   m o d b u s` 一串无法识别的参数。
`-m App_test_fixture` 方式不受影响（它走 `main()` 的默认 `argv=None` → `sys.argv`）。

修法：
```python
raise SystemExit(main(sys.argv[1:] or ["--source", "modbus"]))
```
保留「不带参数默认接 modbus」的意图，同时显式命令行参数优先
（`--source demo` / `--source none --seconds 1` 都能覆盖）。
顺带把从 App_PopPick 复制来的过期 docstring 换成 test_fixture 的说明。

**通用规则**：argparse 的 `parse_args()` 只吃 `list[str]` / `None`；
要传整条命令字符串必须用 `shlex.split(cmd)`，直接传字符串会静默按字符拆。

验证：脚本方式 `--help` / `--source none --seconds 0.3` / `--source modbus
--ip 127.0.0.1 --seconds 0.3` 均 EXIT=0；包方式 `-m ... --source demo` EXIT=0；
`verify_test_fixture.py` 失败 0 项、`verify_point_table.py` ALL PASS、py_compile OK。
modbus 连不上只告警不崩（127.0.0.1 超时 → `连接失败` → 仍用 ModbusDataSource 起界面）。

注：当前现场配置 `MODBUS_IP=192.168.1.88`，**无参数直接跑会真连现场 PLC**；
只想看界面用 `--source demo` 或 `--source none`。

## 修复伺服轴面板数值「只显示一半」（QLabel 裁字，根治）

现象（用户截图）：「当前速度」红圈里显示 `|174.74 mm/s`，首位 `1` 被削成
一条竖线。离屏复现（`tools/verify_value_cell.py`）在**面板宽 468**（图元默认
尺寸）下命中：`1174.74 mm/s` 需 72px，数值 QLabel 只分到 68px。

根因：`ValueCell` 里名称 / 数值两个 QLabel 各 `addWidget(..., 1)` **五五开**，
而 QLabel 右对齐且宽度不足时 Qt **直接从左侧裁掉文字**——没有省略号、
不缩字号、不报错，所以真实值 `1174.74` 看起来像 `174.74`。
这个 bug 家族之前已出现两次，都是靠调版式绕过而非根治：
`columns_for` 注释（5 列把 `99.47 mm/s` 裁成 `.47 mm/s` → 收成 3 列）、
`WriteRow` 注释（QGridLayout 把当前值挤到 40px，`100.00 → 1.00` → 拆双布局）。

修法（`servo_panel.py`）：
- 新增 `_ValueLabel(QLabel)`：覆写 `setText` / `resizeEvent`，用
  `QFontMetrics.horizontalAdvance` 从基础字号往下找能放下**全文**的最大 px
  （下限 7px，可升可降，宽度恢复自动回到基础字号）。**只改字号、不动
  minimumWidth**，因此不顶住 `proxy.resize` 压到图元尺寸的硬约束。
- `ValueCell`：名称 `stretch=0` + `QSizePolicy.Preferred` 按 sizeHint 拿刚好的
  宽度，数值 `stretch=1` + `Expanding` 拿剩余（不再五五开）；数值换 `_ValueLabel`。
- `WriteRow._current` 同样换 `_ValueLabel` + Expanding，`set_current` 补 tooltip。

效果：468 宽下 `fVelocityNow` 从 68px → 93px，字号仍 11px（**布局本身就够，
没靠缩字号过关**）；截图 before `|174.74 mm/s` → after `1174.74 mm/s`。

新门禁 `tools/verify_value_cell.py`：6 档宽度（240/320/430/468/600/964，覆盖
`columns_for` 三档）× 4 个值单元 + 3 个写入行，断言
「当前字体的文本宽度 ≤ label 宽度」「7 ≤ px ≤ 基础字号」「文案未被 elide 加工」，
并额外要求 **468 宽下速度仍是基础字号**（防止以后有人改回五五开布局、
只靠把字缩到很小来蒙混）。同时输出各宽度截图到 `build/preview/`。

`verify_test_fixture.py` 失败 0 项、`verify_point_table.py` ALL PASS、
`verify_value_cell.py` ALL PASS、py_compile OK。

## 新增翻页动画多位整数显示器（`flip_number.py`）

参考 `App_test_fixture/flip_clock.py` 写一个可复用 widget。**不改原文件**：
`App_RackConfig/plc_window.py` 现场用 `FlipDigit_Time_display` 显示 PLC 时间。
原实现三处不适合直接拿来做计数器：把 `self.width/height` 当整数属性
（覆盖 `QWidget.width()/height()`）、动画是 top→bottom 两段串联且只能 `+1`
循环（`FlipDigit` 没有 `set_value`）、`max_value`/6 位/冒号绑死 `HH:MM:SS`。

新文件 `App_test_fixture/flip_number.py` 三个类：
- `FlipDigitWidget`：一位 0~9，**一条** `QPropertyAnimation(flipProgress 0→100)`
  覆盖全程；前 50% `cos` 把旧值上半压扁到中线，后 50% `sin` 把新值下半
  从中线展开。用**离屏 QPixmap 半片**渲染，不用 painter `scale` + `clip`——
  Qt 的 clip 会跟着后续变换一起变形，压缩翻页片时裁切区也被压掉。
- `FlipNumberDisplay`：N 位容器，`set_value(12345)` 逐位比对，**只有变化的位**
  播动画；支持 `digits / leading_zeros（高位熄灭）/ signed / size_factor /
  duration_ms / bg / fg / gap`，越界夹到最大值，非法输入保持原显示，
  动画中再来新值走 `_pending` 排队不丢最终值。信号 `valueChanged` /
  `flipFinished`（所有位动画结束才发一次）。
- `FlipNumberProvider(ControlProvider)`：挂统一运行态 widget 图元，
  `stage.set_mapping({...})` 在 `load()` 前；额外提供 `set_value` 转发，
  `destroyed` 自动清引用，换页重建后恢复最近值。

**踩过的坑**（都写进代码注释）：
- `_fit_font()` 必须缓存**整个 QFont 对象**；只缓存 pixelSize 再拿
  `painter.font()` 重建会退回默认字体族，等宽效果丢失。
- `FlipDigitWidget.set_value()` 不能无条件 `self._blank = False`，否则
  `_apply()` 刚设的高位熄灭状态会被冲掉。
- `ControlProvider` **必须继承**：`MappingProvider._provider` 用
  `isinstance` 判定，不继承会被当 callable 工厂调用 → TypeError。
- 离屏 QPA 字体库为空时 `QPainter.drawText` 连 ASCII 都画不出（空卡片），
  门禁要 `ensure_cjk_fonts()`；新增「亮像素数 > 50 且各帧不同」断言防假绿。
- `deleteLater()` 的 `destroyed` 信号普通 `processEvents()` 不一定派发，
  要 `QCoreApplication.sendPostedEvents(None, QEvent.Type.DeferredDelete)`。

门禁 `tools/verify_flip_number.py` 7 组全绿：格式化（前导零/夹取/负数/非法）、
逐位触发、pending 队列、信号、四档 size_factor 字体自适应、真实渲染帧
（输出 `build/preview/flip_number_frames.png` 五阶段拼图 + 整体示例图）、
provider 挂载链路。`python -m App_test_fixture.flip_number --seconds 1`
是 demo 窗口（带 `--seconds` 便于离屏冒烟）。
全量回归：`verify_flip_number` / `verify_test_fixture`（失败 0 项）/
`verify_value_cell` / `verify_point_table` / py_compile 全绿。

## 翻页计数控件 `_flip_panel` 恒为 None（已修）
- **根因**：`controlCreated = Signal(int, object)` 的第二个参数是**造出来的
  QWidget**（此处 `FlipNumberDisplay`，iid=129），**不是工厂 provider**。
  旧 `_on_flip_created` 写 `isinstance(widget, FlipNumberProvider)` → 恒假，
  回调直接 return，`_flip_panel` 永远 None；控件其实已正常挂进场景。
- **修法（`fixture_runtime.py`）**：翻页计数**不走 controlCreated**，直接把
  `FlipNumberProvider` 实例存进 `self._flip_panel`（新增可选构造参数
  `flip_provider=`）。provider 本身就是稳定门面：`set_value` 转发到 display、
  `create()` 用 `_latest` 补灌换页重建的控件、`destroyed` 自动清 display。
  删掉 `_on_flip_created`/`_on_flip_destroyed` 与 `_flip_panel_iid`。
  `_panel`（伺服面板）仍需 controlCreated，因为它要接 `commandRequested`。
- **同批修掉两处真 bug**：① `_on_values` 原写
  `values.get("axis.total_count", 0)` 后无条件 set_value → 任何别的点位推值
  都会把翻牌清成 0；改成 `if cfg.TAG["total_count"] in values` 才推。
  ② 旧回调 `widget.set_value(self._values)` 把 dict 传给期望 int 的显示控件，
  会静默返回 False。另补 `load()` 末从缓存补灌、`report()` 加 `flip=on/off`、
  `release()` 清引用。
- 门禁 `tools/verify_test_fixture.py` 新增第 11 组：钉死 controlCreated 载荷
  类型、推值同步、推别的点位不清零、reload 补灌、零污染、release 清引用。
  6 套门禁 + CLI demo 冒烟全绿。

## 运行态 vs 设计态「计数控件」位置差异（诊断，未改代码）
- 现象：右侧红框里翻牌数字看起来比设计态白色占位框偏上/偏小。
- 定量对拍 `item.sceneBoundingRect()` vs `proxy.sceneBoundingRect()`：
  8 个 widget 图元里 **7 个 delta 全 0**；只有 id=129「计数控件」左上角一致
  (0,0)，右下内缩 (-14.1,-19.9) → 设计态 350.12×111.89，proxy 336×92。
  视口像素：design (622,485,385,123) / proxy (622,485,369,101)。
- **根因**：`FlipNumberDisplay` 是 `QSizePolicy.Fixed` + `_refresh_size()`
  `setFixedSize(5×64+4×4=336, 92)`（用户已把 digits 改成 5）。
  `WidgetHost.align()` 的 `proxy.resize(350.12,111.89)` 被
  QGraphicsProxyWidget **直接拒绝**（resize 后立刻读仍是 336×92）。
  QSpinBox / ServoAxisPanel / QLabel 非 Fixed，所以 resize 生效、0 差异。
  `align()` 的 `_pose_state` 缓存会在首次之后 return，偏差一旦形成不再修。
- 实测四种修法：只改 sizePolicy → 无效（proxy 缓存旧 geometry）；
  只锁 `setMinimumSize/setMaximumSize` + resize → 有效（proxy 350×111，
  差 <1px）；自适应卡片 + Preferred → proxy 仍 336×92；
  **锁 min/max + 按图元框反推 `digit_size=(67,112)`** → 数字也铺满。
- 预览 `build/preview/pos_diag_compare.png`。待用户定：只改
  `FlipNumberProvider.create()`（不动框架）还是改 `WidgetHost.align()`
  通用修所有 Fixed 控件。
