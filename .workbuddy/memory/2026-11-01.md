## 属性 dock 分页跨图元保留（选中切换时不丢当前页）

问题：切到不同图元时，属性面板的分页总是跳回第一页，而不是停在用户上次停留的页（如「外观」）。

根因：`update_for_selected` 里 `navigation_tree.clear()` + 重建分页时，
`QTreeWidget` 会在 `addTopLevelItem` 第一个节点时自动选中它并触发 `currentItemChanged`，
`on_navigation_changed` 就把 `_last_page_key` 覆盖成了第一个分页的 key，
等 `select_preferred_page()` 恢复时已经拿不到用户原本停留的页了。

修复（`NavigationContentWidget.py`）：
- 新增 `_building_navigation` 标志；`update_for_selected` 用 try/finally 包住
  clear + `_populate_pages`，构建期间置 True。
- `on_navigation_changed` 里写 `_last_page_key` 的条件加上 `not self._building_navigation`，
  只在用户真实点击导航时记录停留页。
- `update_for_selected` 末尾（`_building_navigation` 已重置）统一调 `select_preferred_page()` 恢复。
- 三处内部 `select_preferred_page()`（场景页 `add_navigation_items`、`PropertyItem.add_navigation_items`、
  `run_property.CabinetPropertyItem.add_navigation_items`）都加 `if not _building_navigation` 守卫，
  避免构建期间重复抢先恢复，最终由 `update_for_selected` 统一恢复。

行为：同 key 分页跨图元保留（rect 外观→circle 外观），新图元无该 key 时回退第一页
（text context→rect 回退「常规」）。回归脚本 tools/verify_property_panel.py 40 项仍全通过。

## 属性 dock 分页记忆按「对象类别」隔离（场景↔图元互不污染）

补充问题：从页面背景切回图元后，分页停在「外观」而不是用户之前在图上停留的页。

根因：场景页（页面背景）的导航 key 用了 `appearance`，与图元「外观」页 key 撞名；
更本质的是上一版 `_last_page_key` 是全局单值，场景页回退选中第一项（appearance）时
会把图元上次停留的 key 冲掉。

`update_for_selected` 里先 `_namespace_for(selected_obj)` 得到命名空间（场景="scene"、图元="element"，

行为：rect 停在「布局」→ 切场景 → 切回 rect 仍在「布局」；场景自己的分页也独立记忆。
回归仍全通过。

## 撤销/重做在图元多时卡顿的定位与优化

架构：PageHistory 用「全量快照」——每次 edit 后 capture_snapshot() 序列化整页 JSON，
undo/redo 时 restore_snapshot() 走临时文件 + load_element_info() 全量重建场景。

根因（两层）：
1. **O(N²) 的隐藏排序/清理**（已修）：
   - `SceneManager.addItem` 每个图元 completed 都 `sort_items_by_zValue()`（O(N log N)），
     反序列化 N 个图元 = O(N² log N)。
   - `SceneManager.deleteItem` 每个图元 `copy.copy(m_name_items)` 再遍历整个 name 表清理 = O(N²)。
2. **架构性全量重建**（未改，是设计选择）：每次 undo = 1~2 次全量序列化 + 1 次全量重建，
   O(N) 常数大。100/300/800 图元重建 123/216/885ms，仍偏慢但已是线性。

修复（`myQuadTreeScene.py`）：
- SceneManager 加 `begin_batch()/end_batch()` + `_suspend_sort`/`_sort_dirty`；
  `sort_items_by_zValue` 在 batch 里只置脏不排序，end_batch 统一排一次。
- `deserialize_scene` 反序列化循环包 batch（try/finally）。
- `delete_all_elements` 删除循环包 batch，末尾已统一 clear m_items/m_name_items/m_sorted_items。
- `deleteItem` 在 `_suspend_sort` 时跳过逐条 name 清理（批量删除结束时统一 clear）。

效果：800 图元重建 1343ms→885ms（约 34%）；300→800 由超线性变成基本线性。
回归 40 项全通过，zValue 排序正确性验证通过。

## 吸附（T 键）触发与增量移动修复

需求：按住 Ctrl+左键拖动图元过程中按 T 吸附，图元移动量应等于「光标被拉到
捕捉点的位移」（增量），而非从按下点重算的绝对量。

定位到两个问题：
1. **T 键触发被 `not has_ctrl` 卡死**（`design_scene.keyPressEvent`）：拖图元本身
   就是 Ctrl+左键，按 T 时 Ctrl 仍按着，`not has_ctrl` 恒为 False，`snap_to_current_point()`
   根本不会执行 —— 吸附功能在真实姿势下从未触发。这是核心 bug。
   修复：去掉 `not has_ctrl` 限制（Ctrl+T 当前无绑定，不冲突）。
2. **吸附后图元会回跳**（`myGraphicsScene.move_item_to_snap_pos`）：`warp_cursor`
   把系统光标瞬移到捕捉点，但不触发 mouseMoveEvent，`sence_pos_mouse`/`sence_pos_mouse_save`
   停留在旧值；吸附用 `move_to_pos(pos - sence_pos_mouse_save)` 绝对定位到捕捉点后，
   下一帧 handle_mouse_move 又用旧的 `sence_pos_mouse - sence_pos_mouse_save` 重算，
   图元跳回吸附前位置。
   修复：吸附移动后把图元基准 `set_m_pos_init(child.pos())`、鼠标基准
   `sence_pos_mouse_save = pos`、`sence_pos_mouse = pos` 同步到吸附点，
   让吸附点成为新起点，后续拖动从吸附点累加、不再回跳。

语义说明：`move_to_pos(dpos)` 是绝对定位 `setPos(m_pos_init + dpos)`，`m_pos_init`
拖动中保持不变，故吸附移动量 = 捕捉点 − 当前鼠标 = 光标位移，天然满足「增量」语义；
基准同步只是让这条绝对定位在后续拖动中保持连续。回归 40 项全通过。

## 带 widget_element 的 group 无法保存/使用为模板修复

现象：带 widget_element（或 checkbox_element）的 group 保存为组合模板后，从工具箱
拖出实例化时报「不支持的图元类型: widget」；且实例化出来的 widget 只画占位框不挂真实控件。

本身能成功，真正挂的是实例化环节。

修复（`template_store.py`）：
- import 补 `checkbox_element`、`widget_element`；顶部补 `from Designer.Core.my_common import SceneMode`。
- `ELEMENT_CLASSES` 加 "checkbox"/"widget"，`TYPE_NAME_PREFIX` 加 "复选框"/"控件"。
- `create_template_instance` 创建循环里，`item.completed(True)` 后对 widget_element 补
  `set_widget_readonly(readonly)` + `set_widget_visible(True)`（构造参数 True 走反序列化路径，
  addItem 会跳过承载层同步，不补的话实例化出来的控件只画占位框）。

验证：冒烟确认「rect+widget+checkbox」group 保存 4 节点、实例化成功、widget 承载层恢复

## 图元布尔运算（CAD 交/并/差）MVP 实现

需求：基本图元（rect/circle/triangle）通过交/并/差生成新图元。

核心设计（5 个文件改动）：
- `element.py::base_element` 加 `to_bool_path()`（默认空 path）+ `_map_local_path_to_scene(local_path)`
  辅助（逐 element 用 sceneTransform().map() 映射到场景坐标）。
- `elements.py`：rect/circle/triangle 各自 override `to_bool_path()`（rect 含圆角 addRoundedRect、
  circle addEllipse、triangle 复用 _triangle_path）。
- `elements.py` 新增 `path_element(base_element)`：恒等变换（m_pos=(0,0)、m_transform=identity），
  `_path` 直接存**场景坐标**，局部==场景，布尔结果无需逆变换。实现 paint（复用 triangle 的
  sceneToView 逐点映射模式）、to_dict/from_dict（自包含，存 vertices 顶点列表 + style）、
  clone、check_hover（fill 用 contains，否则 stroker 描边）。type="path"。
- `elements.py` 新增 `boolean_elements(manager, items, op)`：按 op 折叠 QPainterPath 的
  united/intersected/subtracted，结果 `manager.createItem(path_element)` + `completed()`。
  常量 BOOL_UNION/BOOL_INTERSECT/BOOL_SUBTRACT。
- `myQuadTreeScene.py`：import path_element；deserialize_scene 加 "path" 分支；createItem 加
  path_element 命名分支（"路径_"）。
- `template_store.py`：ELEMENT_CLASSES/TYPE_NAME_PREFIX/import 加 path。
- `design_scene.py`：extend_context_menu 加"布尔运算"子菜单（并/交/差，仅选中 ≥2 个可面域图元时
  出现）；`_apply_boolean(op)` = boolean_elements + 删源图元（CAD 替换语义）+ 结果选中。

关键注意事项：
- `boolean_elements` 必须走 `manager.createItem(path_element)`（自动分配 id + set_scene_ref），
  不能裸 `path_element()` 再 addItem，否则 m_scene 为 None、id=0。
- `base_element` **没有** to_dict/from_dict（各子类自实现），path_element 的 to_dict/from_dict

  completed 会把已中心化的局部坐标当场景坐标再算一遍，m_pos 变 (0,0)。
- 冒烟跑 verify_embedded_widget.py / verify_property_panel.py 会重写 page_*.json / project.json，
  跑完必须 `git checkout` 还原（本次已还原 page_1/4.json、project.json）。

待增强（非阻塞）：path_element 选中后属性面板落到"未选择图元"空状态（NavigationContentWidget
的 isinstance 分发没覆盖 path），如需可给 path_element 复用 RectPropertyItem 或加专门分支。
