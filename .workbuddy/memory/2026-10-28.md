## 18:30 修复打包成 exe 后启动崩溃（场景文件没进包）
- 现象：`场景文件不存在，按空场景处理: ...\_MEI671562\data2.json` →
  `AttributeError: 'NoneType' object has no attribute 'set_machine_number'`
  （rack_stores_widget.py:108，场景空 → RackStoreModel.rack() 返回 None）。
- 根因：`--add-data` 没带 `myDesigner/data2.json`；而旧 `get_json_path` 在冻结模式下
  只认 `sys._MEIPASS/data2.json` 一个位置，打包目标写成 `myDesigner` 时也命中不了。
- 修：
  1. `SceneSerializer._resource_dirs()` + `get_json_path()`：依次找
     exe 同目录 → _MEIPASS → _MEIPASS/myDesigner → cwd（源码模式先 myDesigner 包目录），
     取第一个真实存在的；都不存在返回第一候选（exe 同目录），保存也不会写进临时目录。
  2. `handle_rack_status`：rack 为 None 就跳过机台编号；`rack_counts` 容忍 None；
     hmi_config 先校验 index 再取 model，rack_A/rack_B 为 None 时按"不画线"处理。
  3. `RackStatusPanelModel.apply_db12`：`self.group` 为 None 时直接返回。
  4. `RackProcessModel.apply_db12`：长度改判 `<= DB12_TASK_INDEX_OFFSETS`(347)，
     9 个图元任一为 None 直接返回；`move_endpos_to_tagret` 组为 None 直接返回。
  5. 场景为空时只打印一句根因提示，不再刷 9 条"缺少图元"。
- 回归：test/_smoke_frozen.py（路径 5 种情形 + 真空场景构造窗口跑 handle_rack_status /
  apply_db12 / 面板接口 + 正常场景机台编号仍正确）。
- 关键事实：exe 里现场最省事的部署方式是 **把 data2.json 放到 exe 旁边**（最高优先级），
  改场景不用重新打包；打包则要 `--add-data "myDesigner/data2.json;myDesigner"`。
- 打包说明.md 里原本写的是 `myDesigner/data.json`（错，data.json 是旧场景），已改成 data2.json。
