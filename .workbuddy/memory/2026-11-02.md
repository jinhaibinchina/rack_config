
## 普通图元无法覆盖 widget_element（架构性限制）+ 遮挡方案

### 问题本质
- widget_element 的真实控件由 EmbeddedWidgetLayer 用 `QGraphicsView(host)` 承载，是 host 的**子窗口**，永远浮在 host 自绘内容（普通图元 painter 绘制）之上。这是 Qt 窗口系统铁律，无法靠 zValue/raise_ 让自绘图元盖过子窗口。
- 因此"把其他图元移到最前覆盖控件"在当前架构下做不到（handle_go_top 只改场景内部 zValue）。

### 方案（用户确认：运行态、包围盒重叠、变更后实时同步、被盖时隐藏控件退回占位框）
- elements.py widget_element 加 `_widget_occluded` 标志 + `set_widget_occluded()` / `widget_occluded()`：被遮挡时 `layer.set_visible(False)` 隐藏真实控件（不销毁承载层），paint 里 `has_widget_layer() and not _widget_occluded` 才跳过占位框，否则退回占位框绘制（占位框画在 host 上，自然被上方普通图元盖住）。真实控件隐藏后收不到鼠标事件 = 盖住即不可交互。
- myQuadTreeScene.py 加 `_sync_widget_occlusion()`：遍历 m_items，对每个可见 widget_element，若存在 zValue 更高、可见、sceneBoundingRect().intersects() 的普通图元，则 set_widget_occluded(True)。
- 触发点：set_scene_mode（切入运行态）、四个排列动作（go_top/up/down/bottom）、_sync_embedded_widgets_geometry（缩放/平移）、myGraphicsScene.mouseReleaseEvent（图元拖动释放后）。
- 判定口径与 contains_scene_pos 一致（包围盒 intersects），QRectF 已 import。

### 验证
- py_compile 通过；遮挡态切换幂等；遮挡判定算法（高zValue重叠→遮、低zValue→不遮、不重叠→不遮）全通过。

### 注意
- base_element 继承 QObject 而非 QGraphicsItem，zValue/sceneBoundingRect 是自定义实现（element.py 1246/1282）。
- sceneBoundingRect 返回缓存的 _sceneBoundingRect，由 update_boundingRect 维护。
- 后续若需"形状轮廓精确判定"可改用 QPainterPath.intersects，当前是包围盒近似。

### 修复：遮挡后控件再也不恢复
- 根因1（主因）：set_widget_occluded(False) 里有 `and not self._widget_readonly` 条件，但 `_widget_readonly` 在设计态恒为 True（只代表只读展示，不代表该隐藏）。而移动图元只能在设计态做，所以解除遮挡永远不恢复。
- 根因2：遮挡判定没区分模式，设计态也应用遮挡 → 切回设计态想编辑控件时仍是隐藏的。
- 修复：elements.py 把"可见性"与"只读(交互性)"彻底解耦：
  - 新增 `_widget_visible_requested`（场景显隐意图，默认 True）
  - 新增 `_apply_widget_visibility()`：`should_show = _widget_visible_requested and not _widget_occluded`，统一落地
  - `set_widget_visible()` 只记录意图；`set_widget_occluded()` 只改标志；两者都走 `_apply_widget_visibility()`
- myQuadTreeScene.py `_sync_widget_occlusion()`：`self._mode != SceneMode.Run` 时强制 `set_widget_occluded(False)`（设计态控件必须可见可编辑），运行态才计算遮挡。
- 补触发点：`SceneManager.deleteItem` 末尾重算遮挡（删掉遮挡图元后控件要恢复）。
- 验证：遮→恢复、只读态遮→恢复、显式隐藏+遮挡往返仍隐藏、设计态/运行态切换、移走/删除遮挡图元 全部通过。

### 已回滚：遮挡功能整体移除（效果不好，用户要求去除）
- elements.py：删除 `_widget_occluded` / `_widget_visible_requested` / `set_widget_occluded` / `widget_occluded` / `_apply_widget_visibility`；`set_widget_visible` 恢复为「直接显隐」实现；`paint` 恢复 `has_widget_layer() and self._layer is not None` 跳过占位框。
- myQuadTreeScene.py：删除 `_sync_widget_occlusion()` 方法及其全部调用点（set_scene_mode、go_top/up/down/bottom、_sync_embedded_widgets_geometry、deleteItem）。
- myGraphicsScene.py：删除 mouseReleaseEvent 里的遮挡重算调用。
- 结论：普通图元无法覆盖 widget 控件是架构性限制（控件是 host 的子窗口 QGraphicsView，永远浮在自绘内容之上）。以后若再提此需求，先说明该约束，不要直接实现"检测覆盖就隐藏控件"的方案——实测体验差。
- widget_element 现状：`_widget_readonly` 只管交互性，`set_widget_visible` 只管显隐，两者独立；均已恢复原状。
